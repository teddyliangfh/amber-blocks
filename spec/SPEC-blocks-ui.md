# Spec: blocks-ui（精简版，D-030 自主推进）

模块 id：`blocks-ui`。日期：2026-10-13。状态：已实现并在浏览器验证（2026-10-13，Checkpoint 6）；助手自审，边实现边修订。2026-10-14 依据实现审查修订：托盘对象固定、托盘宽高约束与横屏布局、整组内逐块点数。2026-10-16 依据第四轮测评修订：托盘高度按所装的东西封顶并与工作台一起居中、放回区仍是大矩形、8 列工作台用满宽度、点数不再替孩子纠正重复点、吸附虚影中性（D-060、D-065、D-067）。2026-10-18（Phase 20）：合体变身（D-087）、就近吸附（D-085）、托盘点按（D-084）、自由玩数字气泡（D-088）。

## Objective

把 core 的 `BenchState` 画出来，并把手指动作翻译成 core 命令。真实物件手感：抓取点跟手、提起放大加阴影、松手前只有吸附预览、松手后一次提交；取消 / 无效落点弹回原处。不引入 dnd 库，RNGH Pan + Reanimated。

## 结构

```
src/blocks-ui/
  layout.ts        纯函数：舞台几何（cell 像素、工作台 / 托盘矩形、托盘在下或在侧）、cell ↔ px、落点解析、托盘排布与缩放、伙伴内点中哪一块
  tray.ts          纯函数：托盘对象（开题时由材料决定）、固定排布、按当前状态只改占用
  chrome.ts        关卡页上下栏 / 侧栏高度的唯一来源（LevelScreen、AnswerFeedback 与布局测试共用）
  devices.ts       测试用：常见手机竖 / 横屏的舞台尺寸（减去 chrome.ts 的真实高度）
  Spotlight.tsx    提示点亮的环：脉冲三次后常亮，不接收触摸
  CountMark.tsx    点数标记：被数到的块点亮并显示序号
  palette.ts       hue token → 填充 / 边 / 文字色；簇按实际块数取色
  use-draggable.ts Pan + Tap 手势 → translate / scale 共享值；松手回调返回 moved | same | rejected
  Face.tsx         原创简化表情（两只眼 + 嘴），只画在每个簇 / 伙伴的头块
  UnitView.tsx     单位块（托盘或工作台）
  PartnerView.tsx  整组伙伴（托盘或工作台），数字标签贴在身上
  Stage.tsx        工作台网格 + 托盘 + 所有可拖对象；接收 BenchState 与回调 onCommand / onTapUnit / onTapTray / onJoin；合体状态机、接缝光、数字气泡
  DemoHand.tsx     示范手：虚影 + 手指从托盘到工作台（或反过来，Phase 21）
  BossOutline.tsx  Boss 登场：答案大小的虚线轮廓 + 睡脸 + 亮格（Phase 21）；纯函数 `bossOutlineCells`（第二步躲开已拼的，D-097）
  merge.ts         纯函数：`mergedClusters`（含伙伴、≥ 2 个部分的簇：总数、部分、头块、接缝；`apart` 组内各自合体，D-097）；`MERGE_ON` 与合体时长常量
  picture.ts       纯函数：作品册缩略图怎么上色（合体后的样子）
```

## 规则

- 渲染只读**已提交**状态：拖动中的块保持旧颜色 / 旧簇，松手提交后才重算簇（AC-34）。
- 单位块颜色：属于伙伴 → 伙伴主题色（`hueFor(groupSize)`）；松散块 → 所在簇的主题色（`hueFor(簇大小)`）。脸只画在簇 / 伙伴的头块（最上一行最左）。第一章簇上不显示数字标签（点数才是学习动作）；伙伴显示数字标签。
- 落点解析（`resolveDrop`）：元素中心落在托盘区（`trayZone`：画出来的托盘及它下方直到舞台底边的沙地，"画小判大"，D-067）→ 托盘；否则按左上角取最近格并钳到工作台范围内，中心在工作台矩形（外扩半格）内才算；否则 none。占格 / 越界由 core 判定，UI 只画弹回。
- 吸附预览：拖动中按当前位置算目标格，`apply` 试算（不提交）通过则高亮目标格，不通过不高亮。虚影是中性的墨色淡底 + `inkSoft` 虚线（`THEME.preview` / `previewFill`），不是绿色：绿色是"对了"，4 号块也是绿（D-065）。
- 托盘对象（2026-10-14）：开题时由题目的初始材料决定——每个伙伴一个对象、每个松散块一个对象，顺序为内容给定的顺序；之后对象集合与排布不再变化。整组搬出后，原位置显示该伙伴的轮廓；组成员的托盘槽永远不当作独立空槽。搬出 / 放回任何对象，其余对象位置与比例不变。万一某块脱离伙伴独自回到托盘，显示在它在伙伴轮廓内的原格位置。
- 托盘排布（2026-10-14）：按顺序从左到右排行，换行时每行按本行最高的对象计高，行宽与总高（含行距、内边距）都必须放进托盘矩形；所有对象同一比例，从 1 往下找能放下的最大比例；对象一律不溢出托盘。抓起时弹回 1.0。
- 托盘高度（2026-10-16，D-067）：托盘在工作台下方时，只有它装的东西那么高（按 `layoutTray` 的排布行高 + 上下 `TRAY_PAD` + `TRAY_SLACK` 24px），省下的高度让工作台和托盘整体在舞台里垂直居中，下方由关卡页的沙丘接住；放大比例不变（行在小托盘里按同一比例放得下），所以游戏中托盘不会重排。托盘在右侧时不封顶。8 列及以上的工作台（3 + 4）可以用掉左右 12px 边距、贴满舞台宽度。
- 舞台几何（2026-10-14）：托盘在工作台下方（竖屏）或右侧（横屏、宽矮舞台），托盘占用剩余空间（下方时再按上一条封顶）。从最大格子往下找：取托盘方块仍不小于 `TRAY_MIN_BLOCK`（40px，或托盘可用满比例）的最大工作台格子；在"下方 / 右侧"两种排法里取格子更大的那个；都达不到时取托盘方块最大的方案。常见手机竖 / 横屏 × 全题库 × 3 个 variant 的边界检查见 `layout.test.ts`（工作台格子与托盘方块均 ≥ 32px，全部在舞台内、不重叠）。
- 手势：Pan `minDistance 6`，Tap `maxDistance 6`，二者互斥：一次触摸要么是点、要么是拖，不会既计数又移动。抬起放大在 Pan 激活时才发生，点按时块保持原大小，点按坐标对应真实格子。Tap 在工作台单位块上 = 点数。
- 整组内逐块点数（2026-10-14）：工作台上的伙伴仍整体拖动；点伙伴里的某一块 = 数那一块（按点按位置换算成格子，空隙不计）。被数到的块点亮并显示序号；同一轮每块只计一次。
- 点数命中容差（2026-10-14 复审，`countTarget`；2026-10-16 修订，D-060）：点在没数过的块上就数它；点在**已经数过的块上什么也不数**（同一块点两次只有一个数词——孩子一一对应的典型错误不再被悄悄纠正）；点在伙伴外框里的空隙，数手指半格以内最近的未数块（只到上下左右相邻块，不跨对角、不跳远），平局按阅读顺序；半格内都数过则忽略。
- 托盘排布（2026-10-14）：在"按发牌顺序折行""先到先填""先放高的伙伴再先到先填（行内仍按发牌顺序）"三种里取最矮的，平局用第一种；`layoutTray` 按输入顺序返回。17 站在 375×553 上无论发牌顺序都是 34px（原来最差 29px）。
- 落点被拒（占格 / 放不下）返回 `blocked`：弹回时左右摇一下（尊重减少动态效果）；拖到工作台外仍只是弹回。拖动开始 / 结束经 `onDragActive` 通知关卡页。
- 合体变身（D-087）：`merge` 属性为真时（关卡页在答对且第二拍之后，`MERGE_ON = 'success'`；`'touch'` 时一直为真），每个含伙伴、由 ≥ 2 个部分（伙伴，或贴着的一组散块）组成的簇画成一个角色：颜色 `hueFor(总数)`、底板按整个轮廓连成一块（散块也画底板）、只有头块（最上一行最左）一张脸、一个总数徽章（在上排最后一格那块身上）、所有部分同一错开序号并绕角色中心做过关动作。新的一次过关先走一遍：接缝亮 `MERGE_SEAM_MS`（220ms）→ 脸转向对方并眨眼 `MERGE_BLINK_MS`（220ms，同时回调 `onJoin(parts, total)` 给 join 音）→ 换色（`BlockBody` 220ms 渐变），过关动作与 8 砖的车轮等它合完再开始。同一次过关里拆开再合（拿起又放下）只换色。拿起角色里任何一块，这个角色立刻分回（同样的渐变）。挂载时已经是对的工作台（重新打开、岛收尾页、作品册放大）直接画成合好的样子。减少动效：没有接缝光与眨眼，直接换色。只是展示：单位身份、命令、判定都不变。
- 就近吸附（D-085）：落在被占的格子时，`settleOrigin` 在 1 格内按"上下左右、再对角，各按阅读顺序"（`nearbyOrigins`）找 core 接受的位置，伙伴优先选贴住其他伙伴的；吸附虚影用同一个结果；落回自己原位算 same；都不行才 `blocked`。
- 托盘点按（D-084）：托盘里的单块 / 伙伴被点（Tap，与 Pan 互斥）时跳一下（`useCheer` hop，用负数 tick，不会与过关的 tick 撞号），并回调 `onTapTray(n)`（单块 1）。
- 数字气泡（D-088）：`bubbles` 属性里的每一项在那一格上方冒一个伙伴徽章样式的数字，`BUBBLE_MS`（800ms）内淡入、停留、淡出；减少动效时不上浮。
- 示范手反向（Phase 21，D-089）：`demoBack` 为真且 `demoPiece` 是工作台上的伙伴时，虚影从它在工作台上的位置（原大）飞回它在托盘里的轮廓（托盘比例，`DemoHand toScale`）；否则照旧从托盘飞到工作台（`demoTo` 或中间）。减少动效时虚影只在起点闪。
- 示范手搬工作台上的单块（Phase 22，D-102 / D-103）：`demoPiece` 是工作台上的散块时，`demoBack` 为真 → 虚影从它的格子飞回它自己的床位（`plan.slotSpots`）；给了 `demoTo` → 从它的格子飞到那一格（拆开：最右一块放到隔一格）。两者都没给时工作台上的块不被搬（和伙伴一样）。虚影颜色取它所在簇的颜色。
- 过关动作 `launch`（Phase 22，D-104，`cheer.ts cheerFor(n, { boss, countdown })`）：倒数 Boss 剩下的那块蹲一下（压扁）、拉长冲出画面顶部（`LAUNCH_HEIGHT` 900px，480ms 加速）、停一下再从上面落回原位（整段 `LAUNCH_MS` 1.7 秒）。减少动效时与其他过关动作一样不动。
- Boss 轮廓（Phase 21，D-094）：`outline = { n, lit }` 时，`bossOutlineCells` 把 n 格排成工作台中间的一行（太长才折行），画在所有积木之下：每格虚线框（`hueFor(n)` 的 edge 色），前 `lit` 格填 pale 色，第一格一张 `sleepy` 脸；整体 `useBreathe` 呼吸（减少动效时不呼吸）。`pointerEvents="none"`，不参与落点、吸附与判题。D-097：`outline.made`（已拼好、留在工作台上的那一种的格子）非空时，轮廓换到它没占的行：先找不贴着它的行，没有就找不压着它的行，离中间同样远时先下后上（第一种在 8 × 3 的中间一行 → 最下一行；在顶行 → 底行；在底行 → 顶行）。
- 合体分开（D-097）：`apart`（几组单位）给了时，每组只在组内合体，其余照常（`mergedClusters(state, apart)`、`pictureOf(state, apart)`、`Stage apart`、`WorkPicture apart`）。两种拼法贴着摆时，关卡页、作品册、岛收尾页都传各自已拼的几种，显示两个 7，不是一个 14。
- 单块 / 整组语义不混：伙伴整体是一个可拖对象，不能拖伙伴的单块（第二章及第一章 10 / 12 / 17 的握把）；其余第一章站只有单块。

- Phase 21：`Stage.test.web.tsx` 送走站的示范手带着 2 从工作台回托盘（不给 `demoBack` 时工作台上的伙伴不被搬）、Boss 轮廓 5 格亮 2 格 + 睡脸、`bossOutlineCells` 居中与折行；`merge.test.ts` 楼梯一个 6、部分 [1, 2, 3]；`layout.test.ts` 新站不进"比旧工作台小"的比较（它们没有旧工作台），全部视口 ≥ 40px 的清单不变。
