# Spec: blocks-ui（精简版，D-030 自主推进）

模块 id：`blocks-ui`。日期：2026-10-13。状态：已实现并在浏览器验证（2026-10-13，Checkpoint 6）；助手自审，边实现边修订。2026-10-14 依据实现审查修订：托盘对象固定、托盘宽高约束与横屏布局、整组内逐块点数。2026-10-16 依据第四轮测评修订：托盘高度按所装的东西封顶并与工作台一起居中、放回区仍是大矩形、8 列工作台用满宽度、点数不再替孩子纠正重复点、吸附虚影中性（D-060、D-065、D-067）。

## Objective

把 core 的 `BenchState` 画出来，并把手指动作翻译成 core 命令。真实物件手感：抓取点跟手、提起放大加阴影、松手前只有吸附预览、松手后一次提交；取消 / 无效落点弹回原处。不引入 dnd 库，RNGH Pan + Reanimated。

## 结构

```
src/blocks-ui/
  layout.ts        纯函数：舞台几何（cell 像素、工作台 / 托盘矩形、托盘在下或在侧）、cell ↔ px、落点解析、托盘排布与缩放、伙伴内点中哪一块
  tray.ts          纯函数：托盘对象（开题时由材料决定）、固定排布、按当前状态只改占用
  chrome.ts        关卡页上下栏 / 侧栏高度的唯一来源（LevelScreen、AnswerFeedback 与布局测试共用）
  devices.ts       测试用：常见手机竖 / 横屏的舞台尺寸（减去 chrome.ts 的真实高度）
  Spotlight.tsx    提示点亮的环：脉冲三次后常亮，不接收触摸
  CountMark.tsx    点数标记：被数到的块点亮并显示序号
  palette.ts       hue token → 填充 / 边 / 文字色；簇按实际块数取色
  use-draggable.ts Pan + Tap 手势 → translate / scale 共享值；松手回调返回 moved | same | rejected
  Face.tsx         原创简化表情（两只眼 + 嘴），只画在每个簇 / 伙伴的头块
  UnitView.tsx     单位块（托盘或工作台）
  PartnerView.tsx  整组伙伴（托盘或工作台），数字标签贴在身上
  Stage.tsx        工作台网格 + 托盘 + 所有可拖对象；接收 BenchState 与回调 onCommand / onTapUnit
```

## 规则

- 渲染只读**已提交**状态：拖动中的块保持旧颜色 / 旧簇，松手提交后才重算簇（AC-34）。
- 单位块颜色：属于伙伴 → 伙伴主题色（`hueFor(groupSize)`）；松散块 → 所在簇的主题色（`hueFor(簇大小)`）。脸只画在簇 / 伙伴的头块（最上一行最左）。第一章簇上不显示数字标签（点数才是学习动作）；伙伴显示数字标签。
- 落点解析（`resolveDrop`）：元素中心落在托盘区（`trayZone`：画出来的托盘及它下方直到舞台底边的沙地，"画小判大"，D-067）→ 托盘；否则按左上角取最近格并钳到工作台范围内，中心在工作台矩形（外扩半格）内才算；否则 none。占格 / 越界由 core 判定，UI 只画弹回。
- 吸附预览：拖动中按当前位置算目标格，`apply` 试算（不提交）通过则高亮目标格，不通过不高亮。虚影是中性的墨色淡底 + `inkSoft` 虚线（`THEME.preview` / `previewFill`），不是绿色：绿色是"对了"，4 号块也是绿（D-065）。
- 托盘对象（2026-10-14）：开题时由题目的初始材料决定——每个伙伴一个对象、每个松散块一个对象，顺序为内容给定的顺序；之后对象集合与排布不再变化。整组搬出后，原位置显示该伙伴的轮廓；组成员的托盘槽永远不当作独立空槽。搬出 / 放回任何对象，其余对象位置与比例不变。万一某块脱离伙伴独自回到托盘，显示在它在伙伴轮廓内的原格位置。
- 托盘排布（2026-10-14）：按顺序从左到右排行，换行时每行按本行最高的对象计高，行宽与总高（含行距、内边距）都必须放进托盘矩形；所有对象同一比例，从 1 往下找能放下的最大比例；对象一律不溢出托盘。抓起时弹回 1.0。
- 托盘高度（2026-10-16，D-067）：托盘在工作台下方时，只有它装的东西那么高（按 `layoutTray` 的排布行高 + 上下 `TRAY_PAD` + `TRAY_SLACK` 24px），省下的高度让工作台和托盘整体在舞台里垂直居中，下方由关卡页的沙丘接住；放大比例不变（行在小托盘里按同一比例放得下），所以游戏中托盘不会重排。托盘在右侧时不封顶。8 列及以上的工作台（3 + 4）可以用掉左右 12px 边距、贴满舞台宽度。
- 舞台几何（2026-10-14）：托盘在工作台下方（竖屏）或右侧（横屏、宽矮舞台），托盘占用剩余空间（下方时再按上一条封顶）。从最大格子往下找：取托盘方块仍不小于 `TRAY_MIN_BLOCK`（40px，或托盘可用满比例）的最大工作台格子；在"下方 / 右侧"两种排法里取格子更大的那个；都达不到时取托盘方块最大的方案。常见手机竖 / 横屏 × 全题库 × 3 个 variant 的边界检查见 `layout.test.ts`（工作台格子与托盘方块均 ≥ 32px，全部在舞台内、不重叠）。
- 手势：Pan `minDistance 6`，Tap `maxDistance 6`，二者互斥：一次触摸要么是点、要么是拖，不会既计数又移动。抬起放大在 Pan 激活时才发生，点按时块保持原大小，点按坐标对应真实格子。Tap 在工作台单位块上 = 点数。
- 整组内逐块点数（2026-10-14）：工作台上的伙伴仍整体拖动；点伙伴里的某一块 = 数那一块（按点按位置换算成格子，空隙不计）。被数到的块点亮并显示序号；同一轮每块只计一次。
- 点数命中容差（2026-10-14 复审，`countTarget`；2026-10-16 修订，D-060）：点在没数过的块上就数它；点在**已经数过的块上什么也不数**（同一块点两次只有一个数词——孩子一一对应的典型错误不再被悄悄纠正）；点在伙伴外框里的空隙，数手指半格以内最近的未数块（只到上下左右相邻块，不跨对角、不跳远），平局按阅读顺序；半格内都数过则忽略。
- 托盘排布（2026-10-14）：在"按发牌顺序折行""先到先填""先放高的伙伴再先到先填（行内仍按发牌顺序）"三种里取最矮的，平局用第一种；`layoutTray` 按输入顺序返回。17 站在 375×553 上无论发牌顺序都是 34px（原来最差 29px）。
- 落点被拒（占格 / 放不下）返回 `blocked`：弹回时左右摇一下（尊重减少动态效果）；拖到工作台外仍只是弹回。拖动开始 / 结束经 `onDragActive` 通知关卡页。
- 单块 / 整组语义不混：伙伴整体是一个可拖对象，不能拖伙伴的单块（第二章及第一章 10 / 12 / 17 的握把）；其余第一章站只有单块。
