# Brief · Phase 21：合体岛换花样 + 自由玩随机题（给开发 agent）

> 来源：Ted 玩过 Phase 20 后的反馈（2026-10-18）："合体岛的关卡有点单一""希望在沙盒 / 自由玩里加一个随机，随机出数字题、加法题或数字图形题"。Ted 已选：合体岛"换动作"和"加同类新站"两种都要；随机题"跟着进度"出；**先做合体岛，再做随机题**。参考 [docs/play-review-2026-10-18.md](../docs/play-review-2026-10-18.md) §3 F2 / F7、§4.2、§4.3。

## 你的角色与目标

你是 Amber Blocks（给一位四岁、还不识字的孩子做的中英双语数学积木游戏，Expo SDK 58 + React Native Web，手机网页优先）的开发 agent。本轮两个目标：

1. **合体岛不再只有一个动作。** 现在 8 站全是"拖两个伙伴、贴在一起"，只是提示方式不同（指定加数、自由凑、还差谁、两种拼法）。改完后合体岛 12 站，里面有"合成造型""送走多的""三个伙伴搭楼梯""十几"这几种不同的动作，孩子每隔两三站就要换一种想法。
2. **自由玩里有一个"随机题"按钮。** 点一下出一道题，题型和数字都不超过孩子已经玩到的：数字题、加法题或图形题。玩法和关卡一样（云朵、反馈卡、求助、两拍庆祝、合体），但不计进度、不进作品册。

## 任务（按顺序；每节结束跑一次门禁）

### 21-1 内容引擎：三种新动作（content 层，core 不动）

1. **送走多的（`sum_composition.onMat`）**
   - schema：`sum_composition` 加可选 `onMat?: ReadonlyArray<number>`：开局这些大小的伙伴已经在工作台上，从最左列起排成一排、互相贴着、竖直居中（照 `givenMaterial` 的放法，用 core `takeGroup`）；它们照旧在托盘里有 home 槽位（托盘留轮廓，可以拖回）。
   - 规则（`validate` 抛错）：`onMat` 的和大于 `sum`；`allowed` 恰好一对，且等于"把多出的伙伴送走后剩下的那一对"；只有一种送法能剩下一个允许的拼法；多出的伙伴排在两端（送走后剩下的那一对仍然相贴，孩子只需要"送走"一个动作）；`onMat` 与 `given`、`ways > 1` 互斥。托盘里可以没有别的伙伴（`distractors` 可为空）。
   - 题目文案：新 key `prompt.send_away` 中"工作台上多了，送走多的，拼成 {n}" / 英 "Too many! Send one back to make {n}"。
   - 参考解：把多出的伙伴 `returnGroup`。`steps.ts` / validate 的逐步判定照常。
   - 测试（`generate.test.ts` / `validate.test.ts`）：开局位置与 home 槽位、参考解一步、各种非法规格都抛错。
2. **两个以上伙伴合成造型**：已有能力（`quantity_shape` + `handles` + `decoys`，数字岛 8 砖就是）。新增两个模板到 `catalog/shapes.ts`：
   - `TEN_2X5`：两排各 5 格（5 + 5 叠成十）。
   - `STAIRS_6`：三排，1 / 2 / 3 格左对齐的楼梯（1 + 2 + 3 叠成 6）。核对：默认对称是"可旋转、不可镜像"，右对齐的楼梯是左对齐旋转 90° 的结果，也算对；伙伴是刚性的横排，搭不出别的样子。
   - 测试：两个模板都能由参考解搭出来、旋转后的摆法也判对、少一块 / 多一块 / 不连通都判错。
3. **"十几"（`given` 为 10）**：已有能力（`sum_composition.given`）。只需确认 `fitBench` 给出的工作台放得下 10（两排 5）加右边的另一半，托盘里恰好一个能补全。

### 21-3 自由玩"随机题"（跟着进度）

9. **出题（纯函数，`src/content/challenge.ts`）**：输入"孩子已完成的站"和一个种子（以及上一题，避免同一题连着出），输出一道题：先选题型，再用现有的 `materializeNode` 生成（规格 + `fitBench` 工作台 + 一个合成的 ref）。生成的每道题都要过 `validate`。
   - **跟着进度**（默认，规则集中在一个常量里，写清楚改法）：
     - 数字上限 = 已完成站里最大的数（数量站的目标、造型站的块数、加法 / 自由和的和）；一站都没完成时是 3。
     - 数字题（`quantity`）：总是有。目标 1 到上限；超过 6 块单块就用握把（`handlesFor` + 一个 decoy，和数字岛一样，"单块拖拽每题不超过 6"）。
     - 图形题（`quantity_shape`）：完成过第一个造型站（ch1-n3）之后才有；只出孩子在已完成的造型站里见过的模板（方块、转角、长条、塔、砖、以及 Phase 21 的十和楼梯），块数不超过上限。
     - 加法题（`addition_exact`）：完成过 ch2-n1 之后才有；a、b ≥ 1，a + b ≤ min(上限, 10)，托盘里再放一个不同大小的干扰伙伴。
     - 同一题型、同一个数不连着出两次。
   - 测试：同一输入同一种子结果相同；各种进度下只出允许的题型与数字；大量种子生成的题全部通过 `validate`；上限与解锁的边界。
10. **界面**：
    - 自由玩底栏加一个骰子按钮"随机题 / Random"（新画的 `dice` 图标，照 `icons.tsx` 的手绘风格），和"全部收回 / 撤销"同一排。
    - 点了进入随机题页面（建议新路由 `/challenge`，返回就是回自由玩；静态导出与 `vercel.json` / `tools/serve-dist.mjs` 的路由要一起加）。自由玩原来的摆法不动，回来还在。
    - 随机题和关卡一样玩：云朵目标、反馈卡、求助阶梯、示范手、点数、两拍庆祝、合体变身、`join` 音、菜单（继续 / 帮助 / 撤销 / 回自由玩）。**复用** `level-session`、`hints`、`Stage` 与关卡页的做法；不要复制一份 LevelScreen。建议把 LevelScreen 里跟存档有关的部分（`enter` / `complete` / `saveWork` / 作品册 / 解锁 / 下一站）抽成可替换的一层，关卡页和随机题各用各的；改动要能让现有关卡测试原样通过。
    - 随机题不计进度：不 dispatch 任何进度命令、不进作品册、不改 `current`、不解锁；离开或刷新就丢掉这道题（下次进来出新题）。
    - 答对后底栏："再来一题"（accent，骰子图标）+"回自由玩"（sandbox 图标）。"再来一题"出一道新题（不同于刚才那道）。
    - 题目文案沿用现有 `prompt.*`；新 key 只给按钮和菜单（中英各一）。
    - 测试（jsdom）：从自由玩进入、答对后两个按钮、再来一题换题、回自由玩摆法还在、全程没有进度写入（照 Phase 16 数写入次数的测试）。
