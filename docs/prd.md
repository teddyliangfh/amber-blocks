# Amber Blocks：PRD 草案

版本：v0.10  
日期：2026-10-12  
状态：供讨论的产品草案，未批准完整开发范围。用户明确规定第一阶段突出认识数字 / 匹配积木个数，可结合组合形状，第二阶段加入加法；美术参考 Numberblocks 各色数字伙伴。直接拖放与真实取放手感保持为已确认主交互，旧点按主路径及座位任务仍不恢复。

## 1. 产品定位

一个以数字积木为媒介，逐步加入形状拼搭、颜色与规律探索的儿童数学启蒙 App，先给用户自己的四岁女儿使用。

核心价值：让孩子通过触碰、摆放、拆分和组合，看见数量关系，并愿意自主尝试新的做法。

以游戏化短题与探索为主，不以答题速度、使用时长或提前学完小学内容作为成功标准。Numberblocks 的概念递进作为内容设计参考，不是待复制的品牌或素材库，也不默认将视频嵌入 App。

### 1.1 本轮头脑风暴的体验假设

用户反馈确认：积木要像可拿起的物件，从可见盒子直接拖出并放下，不接受按钮取块 / 点格子作为主交互；“给三个座位摆积木”过于无聊，撤下。设计重心改为“动作 → 可见后果 → 再尝试”：拼接、拆开、改结构，让环境或玩具真实响应，不只播报摆对了。故事与角色细节仍未确定。

最新学习主线为“数字小伙伴”：第一阶段建立数字符号与实际单位块个数的对应，并探索同量不同形；第二阶段通过伙伴合体理解加法。小球实验先退出当前主线，不把学数学变成物理游戏。点选 / 键盘仅为无障碍备选，拖放仍是主路径。

用户认可当前交互与 UI，最新要求加入“大章节 → 小关卡（每题）→ 周期性 Boss → 下一章”的主线，地图显示进度。第一章目标数字不机械递增，用户举例 1、2、4、6、9，末关如 17；第二章提供伪随机组合伙伴，如 5、4，完成 3 + 4 = 7 等合体。这些数值是举例，具体路线、难度和 Boss 间隔未最终锁定。当前关卡规范见 [章节地图与关卡](level-progression.md)，取代旧版“自由邀请是唯一主入口”的建议。

设计参考：NAEYC 对 guided play 的说明保留儿童对游戏的主导，同时由成人提供有目的的建议；数字媒介不应替代现实动手经验。[NAEYC 学习与游戏原则](https://www.naeyc.org/resources/position-statements/dap/principles/)。这里将其转化为产品设计假设，不是 Amber Blocks 教育效果得到验证的结论。

## 2. 用户与使用场景

### 儿童

- 当前目标用户：一位四岁、最近喜欢数数和 Numberblocks 的孩子。
- 不预设识字能力、稳定拖拽能力或已经理解加减法。
- 建议支持家长短暂示范后的自主探索，也支持共同游戏。
- 主要设备已确定为手机，可通过手机浏览器打开网站玩；中英双语语音已确认。具体型号、系统、浏览器、数数能力及两种语言的熟悉程度待了解。

### 家长

- 负责启动、陪伴、调整设置与观察试玩。
- 需要知道每个活动在探索什么概念，以及如何用真实积木延续活动。
- 不需要首版提供排名、复杂成绩报告或儿童能力标签。

### 示例场景

孩子看到数字 4，从盒子亲手拖出四块，摆成长条或 2×2 都能对应 4；之后换个摆法仍是四块。第二阶段再把两块伙伴与一块伙伴合体，看到三块及对应的 `2 + 1 = 3`。

这是候选体验，不是教育效果已经得到证明的描述。

### 当前交付方案

- 首轮按手机网页试玩优先设计：打开链接即可进入，不要求先下载 App 或添加到主屏幕。
- 手机触屏是首要适配对象，平板与桌面先作为兼容性考虑，不扩大首轮交互设计范围。
- React Native 保持为已定方向，建议使用 Expo + React Native Web 输出网页，并为后续原生版本保留共享逻辑与界面。
- 全屏是渐进增强功能，不应成为开始游戏的门槛；具体横竖屏尚未确认。
- 原生安装版、商店发布和完整离线缓存不因“支持手机网站”而自动进入首版范围。

## 3. 学习与体验目标

| 目标 | 可观察行为 | 候选活动 |
|---|---|---|
| 一一对应地数物体 | 每块积木计一次，不反复把同一块当成新物体 | 点数积木 |
| 理解数词与总量的联系 | 点数结束后，能用最后的数词表达“有几块” | 点数积木、搭出数量 |
| 连接数量与数字符号 | 看见三块积木与数字 3 的对应关系；不要求先识别所有数字 | 搭出数量 |
| 初步体验部分与整体 | 把三块拆成一块和两块，再重新合成三块 | 拆开与合并 |
| 探索排列与数量 | 改变形状与位置，观察总数仍保持不变 | 共享积木空间 |
| 探索形状与空间 | 用同样的方块搭出不同外形；后续尝试用几何拼片组成图案 | 自由拼搭、后续几何活动 |
| 观察属性与分类 | 按颜色或形状整理物体，并描述自己的分类方式 | 后续分类活动 |
| 发现重复规律 | 模仿、继续或创造简单的颜色 / 形状序列 | 后续规律活动 |
| 保持主动探索 | 尝试未被提示的新排列，能撤销、重来或讲述自己的发现 | 所有活动 |

课程参考：EYLF V2.0 的兴趣导向、个体差异与游戏化学习；Foundation 数学的数量表征、点数及部分—整体关系。[EYLF](https://www.acecqa.gov.au/nqf/national-law-regulations/approved-learning-frameworks)、[ACARA 数学参考](https://www.australiancurriculum.edu.au/resources/work-samples/mathematics/foundation/ws03-numbers-to-20)

这是内容设计关联，不是正式课程认证；Foundation 年级目标不应作为四岁儿童的强制进度。州和学校体系确认后再补充正式映射。

### 3.1 Numberblocks 难度参考

用户已明确提出参考课程 / 视频的难易程度。根据官方学习说明，Level 1 以 1–5 为范围，包含点数、少量数量的直接识别、比较与简单加减；Level 2 扩展到 10，并加入更多拆合关系、形状和规律等内容。[Numberblocks 官方分级](https://www.blocksuniverse.tv/numberblocks/how-it-works)

首轮可参考以下已核对的概念锚点，而不是逐集复刻：

| 参考内容 | 对应概念 | Amber Blocks 原创活动建议 |
|---|---|---|
| Series 1，Episode 10：How to Count | 每个物体数一次；最后的数词表示总量 | 点数、标记已数的积木，再表达总量 |
| Series 1，Episode 11：Stampolines | 换排列不改变数量 | 同样四块搭成长条或 2×2，再数一遍 |
| Series 1，Episode 12：The Whole of Me | 一个整体可拆成部分，合回仍是原总量 | 三块分成一块和两块，再合起来 |

概念依据：[NCETM Series 1 教学说明](https://ncetm.org.uk/classroom-resources/ey-numberblocks-series-1/)。这些是参考资料中的教学目标，并非本产品已实现或已验证的学习效果。

- 按概念和实际操作难度组织内容，不把视频播放顺序当作强制关卡顺序。
- 看过某集、会背数词，不等于已能独立点数或理解该概念；是否扩展依据试玩观察和家长选择。
- 不以年龄、看过的集数或答题速度自动解锁 / 锁住内容；首轮不实现复杂能力评分或自适应推荐系统。
- 数量、形状、颜色和操作复杂度分别控制；同一小任务先突出一个目标，不同时增加所有难度。
- 参考资料与活动映射供产品设计 / 家长说明使用；首版不引入视频播放、角色素材、歌曲或脚本复用。

### 3.2 三条探索线，共用一个操作空间

| 探索线 | 起步建议 | 后续增加 | 观察什么 |
|---|---|---|---|
| 数感 | 1–3 起步，可在建议的 1–5 范围自由取放、点数 | 搭出数量、换排列、拆合，再考虑 6–10 | 能否数清楚、表达总量、发现不同分法 |
| 形状与空间 | 相同单位方块搭塔、长条、转角或 2×2 | 独立几何拼片：圆形、三角形、正方形等组成图案 | 是否主动换摆法、转动拼片、解释图案 |
| 颜色与规律 | 少量颜色自由配色，颜色不决定数字 | 按颜色分类，再模仿 / 接续 AB 重复序列，如红蓝红蓝 | 是否尝试不同配色、分类或发现重复单元 |

上述活动与分期是设计建议，不表示三条线全部进入首轮原型。自由探索可以把属性自然结合，但引导任务只突出一个概念。例如四块积木既能换颜色，也能搭成不同外形；不必同时规定数量、配色、形状和摆放顺序。

难度不仅是“数字变大”：也包括目标数量、排列复杂度、动作精度与语音语言熟悉程度。建议一次只增加一个变量，允许家长选择更简单体验；不做年龄等级、自动能力评分或看完某集就升级。参数与小邀请见 [首个玩法与内容实验](first-play-and-experiments.md)。

澳洲课程关联：Foundation 的熟悉形状命名、分类与创造，以及重复规律，与这些候选活动有对应关系；官方样例也包含按颜色和形状整理物体。[ACARA 形状与分类样例](https://www.australiancurriculum.edu.au/resources/work-samples/mathematics/foundation/ws02-sorting-shapes-and-objects)。颜色自由创作本身不被包装成完成数学课程指标。

### 3.3 已确认的两阶段顺序

| 阶段 | 核心学习目标 | 候选体验 | 不提前要求 |
|---|---|---|---|
| 第一阶段 | 认识数字符号，匹配真实单位块个数；同量不同形 | 认识伙伴 → 拖出对应数量 → 手动变形 | 算式填空、加法答题或物理实验通关 |
| 第二阶段 | 两组具体数量合起来的加法 | 伙伴合体 → 数总量 → 显示对应加法 | 限时口算、减法 / 乘法或自动能力评分 |

这一顺序来自用户，不等同于 Numberblocks 官方 Level 1 / Level 2。当前采用章节地图进阶，具体数域与题表仍待确定；原 1–5 只是旧原型范围，不是正式上限。[两阶段学习与数字伙伴](learning-stages.md) 与章节文档共同记录当前内容。

## 4. MVP 候选范围

首轮工程建议先做三道普通题与一个 Boss 的完整地图闭环。用户已提出 6、9、17 等更大数；初始数域、17 是否进入首章主线与触摸支持待收敛，不以旧五块托盘作为正式上限。

第一版已确认支持中英双语语音，覆盖进入原型范围的核心数数、操作引导与反馈；具体播放方式见第 5.2 节。

第一轮主轴保持鲜明数字伙伴与直接拖放。当前独立可玩切片已连接四站（1、2、4 方阵、3 转角 Boss）、实际判题 / 地图 / 重玩与一个 3+4 整组合体样例；无“预览过关”按钮。完整题库、17、语音与正式工程范围仍需收敛，详见 [首个可玩关卡切片](playable-slice.md)。

### 4.1 有限托盘与直接拖放

- 盒子里能看见真实可抓取的块，不通过“拿一块”按钮凭空复制。拖走后原槽空出来；拖回盒子收好。
- 旧原型用五个固定身份单位块；章节按目标提供足量有限材料，不受五块上限限制。每题材料含稳定单位身份；颜色保留已认可的鲜明伙伴方向。
- 手指按住的抓取点跟随移动；提起有阴影 / 轻微抬升，松手有短落定反馈，画面不抢手指。
- 工作台自由放置，不显示必须填满的棋盘格；近邻接边显示吸附预览，松手才提交。
- 普通单位块题一次移动单块，接边不默认绑住整座作品；组合伙伴题 / 大伙伴支持用明确握把移动整组，抓取语义须示范，不隐式切换。
- 从盒到桌、桌到盒的库存守恒；取消、失焦、拖出无效区域回到拖动前的稳定状态，不丢块、不复制。
- 撤销还原一次提交的拖放 / 收回，不记录每帧位置。点选 / 键盘备选不能成为主体验。

### 4.2 第一阶段：数字与个数匹配

- 数量始终由真实单位块身份决定，颜色、外形与阴影不改变数值。
- 选择数字 n 后，大数字与所需个数的含义保持清楚；拖出 n 块才匹配。只看实际单位块个数，不要求同色、全部相接或唯一排列。
- 接边可让单位块组成有表情的伙伴；连接组主题色依实际组数量更新，但学习目标仍是数字与总个数，不以颜色作为匹配依据。
- 拖动中的分组只是预览，隐藏过渡数量；提交后再更新，不把暂时遮挡或拉起当作新增 / 消失。
- 自由模式改选数字保留作品；闯关模式匹配后点亮地图、提供“下一站”，明确转场后更换题目和材料，不悄悄清空正在变形的作品。具体自动转场待确认。手指点数与数词语音是配套设计，不宣称目前文字草图已提供声音。
- 仅匹配数量时，四块长条、2×2 或自由排列都对应数字 4；形状关必须预先展示轮廓并配置平移 / 旋转 / 镜像判定，不临时增加隐藏目标。

### 4.3 第二阶段：伙伴合体与加法

- 两个伙伴的数字与单位块数量先对应正确；通过明确的整组合体动作体验“二块和一块，一共三块”。
- 合体保留同一批单位身份，不能靠遮挡 / 替换动画假造总量；得到总量后再显示 `2 + 1 = 3`，不先要求输入答案。
- 先设计小集合的加法，如 1+1、1+2、2+2；和的正式上限及到 10 的进度待确认。
- 第一阶段以单块取放为主；第二阶段若拖整组伙伴，必须明确操作对象，不能悄悄改变手势语义。
- 3+4 已有独立整组拖放样例；完整加法章与正式工程未实现。小球、塔、过河车等不列为当前两阶段必做内容。

#### 4.3.1 第二章组合备选

用户要求备选区出现组合伙伴并伪随机变化。题目 3 + 4 可提供洗牌的 [5, 3, 2, 4]，每组必须确有标示数量的真实单位；a = b 的题须提供两个不同组身份。指定操作数题与“自由拼出 7”分开，后者可接受 5 + 2。来源单位守恒，先合体再揭示和；不会凭标签相加。独立切片已实现 3+4 样例及确定性选项洗牌，尚无 a=b 玩法、自由和、完整加法题库或正式工程。

#### 4.3.2 章节地图与 Boss

- 每小关卡是一题，完成后下一站可开始；已完成节点可重玩，重玩不倒退最远进度或重复计数。
- 每 3–5 道普通题一个 Boss 为候选节奏；用户确认周期性 Boss，但未确定频率。Boss 增加组合 / 造型挑战，不增加倒计时或生命惩罚。
- 用户举例的大目标 17，可用明确 10 / 5 / 2 组合握把减少重复取放，并提供更大数字点数支持；不要求第一章填写加法算式。不缩小单位触摸区域来硬塞 17 个按钮。
- 地图与题参数分离，seed / 内容版本 / 节点 / 变体可复现；生成后不因返回或切语言重抽，必须验证可解性。详细状态与随机规则见章节文档。
- 建议成功反馈后由“下一站”前进，允许随时回地图 / 结束；家长可选择章节或帮助，不把解锁当作能力认证。本地持久进度尚未实现。

### 4.4 拆开、拼接与变形

- 手把一个单位块从连接簇拉开，再接到另一边；数量随明确的接边关系更新，全体身份保持不变。
- 同样四块可拼高或拼宽，匹配数值仍是 4；拆掉一块才会改变个数。正式加法合体在第二阶段，不把拆合过程混说成第一阶段算式教学。
- 撤销还原数量、位置和接边关系；所有块仍属于托盘或工作台，不能出现第三处失踪库存。
- 后续若采用分组区域，需要与连接簇区分；组数、材料块数、面积是不同概念。

### 4.5 形状组合与颜色组合：分期建议

用户已提出两类组合探索；以下是收敛范围的建议，而非已确认的完整功能清单。

1. 首轮：用鲜明的角色主题色、清楚单位边界与原创表情认识数字伙伴；通过拖放个数与组合变形建立数量对应。实际数值只由单位身份决定，主题颜色不代替数学判断。
2. 试玩后：按颜色整理积木、红蓝红蓝等 AB 规律；之后再考虑 AAB / ABC 等不同重复单元。允许自由创作序列，不对没有任务目标的排列判错。
3. 后续形状活动：在单独的几何拼搭模式提供圆形、三角形、正方形等；例如三角形作屋顶、正方形作墙，拼成自己的小房子。若做轮廓匹配，支持宽松吸附和任务允许的不同摆法。

必须区分两种“形状组合”：

- 数字积木的重排：四块仍是四块，2×2 与长条只是外形不同。
- 几何拼片的组合：拼成一个图案不等于只剩一块材料；若播报数量，明确说“用了几块拼片”，不能把拼片数量、组数和面积混为一谈。几何拼片与计数单位方块不混用同一套数值语义。

“颜色组合”暂按自由配色、分类与规律理解，不默认包含颜料混色。若用户希望调色，需单独确定是模拟颜料还是光，以及交互和结果规则；不使用简单的颜色编码平均值来代表真实颜料混合，也不暗示两块彩色积木靠在一起就会自动变色。混色不进入首轮。

### 4.6 其他后续候选，不进入首轮原型

- 专门的轮廓匹配、旋转与空间位置活动。
- 多一个 / 少一个。
- 6–10 数域、少量物体的快速识别和比较多少；颜色 / 形状规律分期见第 4.5 节。
- 搭高塔让小动物爬上去、接桥让小车实际过河、拼会动的积木小生物；都应有可见行动后果，不能只把固定数量题换皮。桥与小生物本轮尚未实装。
- 更丰富的原创角色、家长活动建议及更多双语内容；基础中英语音支持已属于第一版范围。

### 4.7 首个玩法的闭环与内容池

工作名“数字小伙伴”：认识数字 n → 从托盘直接拖出单位块 → 用真实个数匹配 n → 亲手换形状，仍是 n → 选择另一个数字或结束。第二阶段才以两组伙伴合体突出加法。

“三个小座位”与点按取块 / 格点移动作为主方案已被用户否定，不保留为当前候选默认。塔、桥、小生物是更有行动后果的内容提案，不代表三类立即一起开发。

当前两阶段玩法与美术方向见 [两阶段学习与数字伙伴](learning-stages.md)；此前 [拖放与结构实验记录](first-play-and-experiments.md) 只保留手感历史与后续参考，不再是当前首个教学闭环。

### 4.8 数字伙伴的视觉语言

用户要求参考 Numberblocks 各色 blocks；当前采用鲜明红、橙、黄、绿、蓝和“几个单位块构成一个数字伙伴”的思路。[官方伙伴介绍](https://www.blocksuniverse.tv/numberblocks/how-it-works)

- 数字大、单位边界清楚，脸与颜色辅助记忆，不遮住块数。
- 表情与角色简化为原创设计，不复用官方服装、眼睛特征、角色图、音乐或视频素材。
- 主题色可以稳定关联角色，但匹配只按真实个数；不能让孩子仅靠颜色完成所有数量活动。
- 本轮样式不是最终原创美术或商业素材许可审查结论。

## 5. 交互与内容设计原则

- 一屏只突出一个主要操作或目标，不依赖阅读长说明。
- 用简短语音、清晰示范和稳定的视觉反馈引导；语音可重听，也可静音。
- 触摸区域和吸附范围应宽松，以手机可用视口为基准；具体尺寸需要真机验证，不固定单一型号的屏幕尺寸。
- 颜色不能成为唯一线索，数量、形状或标记应提供辅助信息。
- 颜色探索也应提供可选的颜色名称语音 / 标签等辅助；不能只靠“绿色表示对、红色表示错”，或靠颜色区分已数 / 未数状态。形状与数量不永久绑定到某个颜色，允许观察同色不同形、同形不同色。
- 动画用于说明发生了什么，不遮挡积木，也不长时间锁住操作。
- 对错误尝试给描述性提示，不羞辱、不扣分、不制造失败焦虑。
- 提供用户要求的章节闯关与地图进度，但不使用倒计时、排行榜、强迫连续游玩、签到奖励或随机奖励箱。
- 设置自然结束点，允许孩子退出；产品不以延长停留为目标。
- 原创角色可以表达情绪和鼓励，但不通过索取陪伴或难过表情迫使孩子继续。
- 为音频、视觉素材建立来源与许可记录；商业发布前核查权利。

### 5.1 手机网页与全屏体验

区分三种模式，不把铺满网页误称为隐藏浏览器与系统界面的真正全屏：

1. 普通浏览器模式：游戏铺满当前可用视口，保留必要的浏览器界面；不支持真正全屏也能完整玩。
2. 真正全屏模式：检测当前浏览器能力，提供用户点击触发的入口，处理拒绝或失败；有清楚的退出方式，退出后保留积木状态。
3. 主屏幕启动模式：可选提供名称、图标和显示配置，让家长添加到主屏幕并独立启动；可能仍有状态栏或系统手势区域，不承诺无系统栏。

设计与实现要求：

- 不在网页加载时强制请求全屏；不自动反复把用户拉回全屏。
- 不支持或拒绝全屏时，不出现阻断游戏的错误弹窗，也不显示误导性的“已经全屏”状态。
- 主屏幕操作说明放在家长帮助中，可跳过；全屏与添加到主屏幕都不是首次试玩的必要条件。
- 适配刘海、底部手势区域、地址栏展开 / 收起和视口变化，关键按钮与积木不得被遮挡。
- 横竖屏切换不得重置数量或丢失积木；布局优先方向待确认，不强制依赖网页锁定方向。
- 拖动时避免游戏区域误滚动；不以禁用所有浏览器缩放或导航能力作为默认方案。
- 首次语音播放结合“开始玩”的点击处理浏览器播放限制；播放失败时仍有可理解的视觉反馈。
- 首次访问与素材加载需要网络；加载后断网续玩、缓存和断网重启属于待确认范围，不因主屏幕入口而默认实现。

依据：[Fullscreen API 的触发与兼容边界](https://developer.mozilla.org/en-US/docs/Web/API/Element/requestFullscreen)、[主屏幕显示模式](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Manifest/Reference/display)、[移动浏览器音频播放限制](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay)。

### 5.2 中英双语语音

已确认的范围是支持中文与英文，不表示用户已经选择同时播报两种语言。

建议的最小方案：

- 家长选择本轮主要语言“中文”或“English”；每次只播放当前语言，默认值待确认。
- 两种语言覆盖同一套核心内容：数词 1–5、开始 / 重听等必要引导、总量表达和温和反馈；颜色、形状与规律活动进入范围时，同步补齐相应的名称与操作语音。
- 例如同样三块积木，中文可说“三块积木”，英文可说“Three blocks”；两者指向同一个游戏状态。
- 换语言不更改活动、积木、数量或分组；停止旧语音队列，随后按新语言重听提示，避免两种声音叠加。
- 建议必要的界面与家长说明提供对应中英文案，但儿童不依赖识字，也不要求把每条文案同时挤在手机画面上。
- 语音建议采用准备好的短音频，保持表述与声音一致；不把在线实时翻译、儿童语音识别或开放式 AI 对话加入首轮范围。
- 默认语言、中文音种、英语口音、录音制作方式，以及是否需要中英连续播放，仍待确认。

语言支持是已确认需求；上述切换、文案和制作方式属于待确认的实现建议。

### 5.3 直接操作与稳定数学状态

- 主路径只有抓取、移动、松手和拖回，不要求先点击选中、再点格子；轻触不同时取块与计数。
- 拖动只改变临时视觉，松手有效放置才提交；无效落点 / 取消恢复原处，边缘不等于删除。托盘收回是可见的明确动作。
- 接边吸附先预览再提交；允许自由放置、允许拉开，单块拖动不意外搬整组。过渡中隐藏簇数量，稳定后重算。
- 当明确设计可选计数时，仍区分已数进度与总量，集合改变停止旧计数 / 声音，单块重排不生成身份；拖动不得额外触发点击计数。
- 换语言保留物体与有效计数状态，声音队列规则仍适用；不把英文不熟悉当作数感不理解。
- 首轮无超时催促，作品或实验没有固定审美答案；反馈描述有效状态 / 行动后果，不自动宣称孩子学会知识。
- 退出即时结束声音、球与未提交手势，保留稳定作品；不要求完成任务或通过家长门。关闭 / 刷新恢复另行确认。

### 5.4 物件主导的手机界面

本轮数字伙伴草图继续保留直接拖放，但主视觉改为鲜明角色、大数字、可见单位身体与数量匹配，不继续旧木质两色或小球主玩法。

- 数字伙伴选择位于上方，主区域保留自由拼搭和实际总量反馈；托盘是真实可拖对象，不使用取块按钮。语言收在家长区，家长门 / 全屏仍待实现。
- 阴影、抬升、接边预览、落定反馈为手感服务；不使用长庆祝锁操作，也不以屏幕震动支持作前提。
- 本轮新草图覆盖第一阶段拖放与数量匹配，不实装加法；仍不是 React Native 工程，没有正式语音、真机或儿童验证。
- 竖屏、1–5、具体造型与颜色数值仍是原型假设；用户已确认的是鲜明数字伙伴参考及两阶段学习顺序。

详细手感、托盘语义、接边关系与未覆盖项见 [手机界面与入口方案](phone-interface-design.md)。

## 6. 功能验收草案

| AC-01 | 无论积木如何排列，显示和播报的总量与真实积木数量一致。 |
| AC-02 | 一轮点数中，每块积木最多增加一次计数；重复触碰不会重复增加。 |

| AC-04 | 合并与拆分前后，全部积木的总数保持不变；撤销能恢复一致状态。 |

| AC-09 | 首轮至少在用户的一台真实手机上验证；对外发布前覆盖目标版本的 iPhone Safari 与 Android Chrome，并记录设备 / 系统 / 浏览器版本及实际支持模式。 |
| AC-10 | 首轮体验在家长短暂示范后是否可理解，通过观察记录验证，而不只看自动测试通过。 |
| AC-11 | 支持 Fullscreen API 时，点击可进入和退出；以实际事件 / 状态更新界面，而非点击后就假定成功。 |
| AC-12 | 不支持、请求失败或用户拒绝全屏时，仍能完成首轮玩法；不要求安装或添加到主屏幕。 |
| AC-13 | 进入 / 退出全屏、旋转屏幕及浏览器视口变化后，积木数量与分组不变，主要操作区域仍可见。 |
| AC-14 | 如提供主屏幕启动，图标与名称正确，独立窗口中可正常开始、返回与退出；如保留系统栏，不误报为真正全屏。 |
| AC-15 | 地址栏展开 / 收起、刘海与底部安全区域均不遮挡关键按钮；积木拖动不会造成非预期页面滚动。 |
| AC-16 | 首次点击开始后可以尝试播放语音；浏览器阻止播放或静音时，视觉示范仍使游戏可用。 |
| AC-17 | 首轮范围内所有核心数数、引导和反馈语音都有中英版本，表达的目标数量与操作含义一致。 |
| AC-18 | 按建议方案切换语言时，积木、分组及活动状态不变；旧语音停止，新旧语言不叠加播放。 |
| AC-19 | 两种语言下都可完成同一个核心玩法；孩子不必阅读文字才能理解主要操作。 |
| AC-20 | 对已有积木换色、重排或旋转，不改变积木身份与数量；一块的颜色不决定它代表的数值。 |
| AC-21 | 自由拼搭允许不同外形与配色；仅要求数量的任务不因颜色 / 外形不同而拒绝正确数量，也不要求唯一排列。 |
| AC-22 | 后续几何活动如播报数量，明确计数单位是拼片而不是组成的图案 / 面积；形状识别不因旋转而改变名称，匹配规则容许任务定义内的合理摆法。 |
| AC-23 | 后续分类与规律任务有明确目标属性 / 重复单元；自由模式不把孩子自创的颜色、形状排列判错。 |
| AC-24 | 新增颜色 / 形状活动的中英版本描述相同属性、操作和计数单位；触摸目标、已数标记及反馈不依赖颜色作为唯一线索。 |
| AC-25 | 托盘取出、桌上移动、拖回收好均通过直接拖放主路径完成，不要求点取按钮或先选中再点格子；无障碍替代单独验证。 |
| AC-26 | 单块题一次有效拖放只移动一个稳定身份；明确整组题移动该组身份集合且只提交一次。取消不提交，不额外计数或复制；不能完全重叠或被工具栏遮住。 |
| AC-27 | 点数中重排保留已数身份；集合增加、减少或换对象后，旧轮次与所有待播总量失效。三块已数两块后增加第四块，不继续播旧“三块一共”。 |
| AC-28 | 部分计数显示 / 播报“已数几块”，完成才以本轮总量反馈；静音、音频失败或重听时不把计数进度误报为真实总量。 |
| AC-29 | 快速点完五块，视觉标记及时出现，数词顺序一致且不叠加，总量在数词后；取消轮次、切语言或退出后无旧反馈残留。静音不强制等待录音长度。 |
| AC-30 | 空舞台有可理解的无积木状态；清空后撤销可还原块数 / 身份 / 位置 / 颜色，不恢复过期计数或音频。 |
| AC-31 | 未数完也可立即退出且停止声音；本次页面内返回按建议保留舞台。刷新 / 关闭后是否恢复不被默认为已实现。 |
| AC-32 | 小邀请可忽略，提示不自动完成真实操作；系统只描述已验证的状态，不凭任意摆法宣称孩子学会知识或识别出房子 / 桥。 |
| AC-33 | 抓取点跟随指针，提起与落定可见；真实触摸与鼠标均可拖放，第二根手指不复制块，取消 / 失焦不丢块。 |
| AC-34 | 接边预览在松手前不改变稳定分组；拖动时不显示过渡簇数量，松手后数量对应明确连接关系。拉开子块只移动子块，不意外移动整簇。 |
| AC-35 | 托盘与工作台的有限库存总数守恒；拖走有空槽、拖回恢复，所有块始终归属托盘或工作台。 |
| AC-36 | 小球实验如进入正式范围，落点 / 碰撞根据当前结构计算，不沿旧预制路径播放；退出可停止，不以结果判题，也不把简化物理宣称为真实准确。 |
| AC-37 | 第一阶段数字 n 的示例身体确有 n 个单位；匹配根据工作区实际个数，不根据颜色、形状或是否全部连接。四块长条与 2×2 都匹配 4。 |
| AC-38 | 改选目标数字不自动替换作品；拖回一块后匹配状态立即依据新个数更新；拖动中不报完成，取消不造成假匹配。 |
| AC-39 | 第二阶段如进入实现，操作数、结果、语音和算式均对应真实单位身份；合体前后总材料守恒，不重复计同一块。 |
| AC-40 | 第一阶段不强制算式作答；第二阶段先显示具体两组 / 合体，再提供对应加法。两阶段不能因为同一拖动动作而混用单块 / 整组语义。 |
| AC-41 | 地图区分已完成 / 当前 / 未到达；有效答题只提交一次完成，重玩不重复增加总进度或撤回后续解锁。 |
| AC-42 | 匹配后短反馈与下一站可见；回地图 / 退出始终可用。未完成回来保持原题，不因导航 / 切语言变题；刷新恢复按实际存储范围另测。 |
| AC-43 | shape 题预先展示目标，模板单位数等于数字；平移 / 旋转 / 镜像按配置测试。quantity 题不因不同外形拒绝正确数量。 |
| AC-44 | 固定 seed / 内容版本 / 节点 / 变体可复现题与托盘；随机选择在难度带内，避免无解。3+4 备选含两个真实组，2+2 含两个不同身份的两块组。 |
| AC-45 | 指定 3+4 与自由拼出 7 判定分离；后者允许配置内的 5+2，前者提示目标组而不否定 5+2 的总量。 |
| AC-46 | Boss 与下一章依据稳定完成状态开启，不由预览 / 假动画解锁正式进度；17 的实际身体确有 17 单位，明确整组握把，不用过小按钮或假单位凑数。 |
| AC-47 | 换题后旧拖动、撤销、数词与反馈不污染新题；保存只含稳定作品与有效完成集合，内容升级不把旧序号错误套到新题。 |

以上是正式 App 的后续实现和测试目标，尚无正式工程或产品测试结果；本轮独立界面草图的点按 / 布局检查不能被视为这些条件已全部通过。后续活动仅在进入开发范围后验收，不要求首轮提前实现全部活动。

## 7. 信息架构草案

首版尽量保持浅层结构：

- 儿童首页 / 章节地图：继续当前站、已完成与未到达的路径、Boss 及下一章；手机浏览器可开始，不先安装。自由拼搭是补充入口。
- 关卡空间：只突出当前大数字 / 造型 / 合体目标、直接拖放工作台与可见托盘。用户明确否定常驻品牌栏、关卡横排与进度行，不用新的常驻工具栏替代；小菜单按需打开地图 / 切语言，成功后下一站。第二章托盘使用有真实单位的组合伙伴。
- 家长区：声音、中英语言选择（建议方案）、使用说明、可选主屏幕启动帮助和现实活动建议。

家长活动说明建议为“一个概念、一句问题、一个现实动作”，不生成成绩或能力标签。未来作品墙、内容卡等是候选，不因本轮信息架构讨论进入首轮。

家长区的保护方式待设计。未来若出现购买或外链，需要按目标平台要求设置家长门；家长门与隐私同意是不同事项。[Apple 审核要求](https://developer.apple.com/app-store/review/guidelines/#kids-category)

## 8. 技术约束与建议

- 用户已确认 React Native；Expo + TypeScript 是建议默认方案，尚未创建工程。
- 当前方案手机网页优先，建议采用 React Native Web；核心界面优先使用跨端组件。
- 数学与数量规则独立于绘图和音频，便于单元测试。
- 内容按概念记录数域、目标、前置经验、形状 / 颜色属性、提示和双语资源；Numberblocks 参考出处作为资料元信息，不作为代码中的强制关卡编号。首轮用静态内容即可，不增加内容后台。
- 先用最少的依赖完成一个玩法，必要时再加入 SVG、手势和动画库。
- 用稳定身份标识每块积木，分离数量 / 分组状态与屏幕坐标；坐标变化不等同于数学变化。
- 区分拖动预览与提交状态、托盘库存与桌上材料、明确接边关系与附近距离。即时跟手与吸附需独立验证，不因桌面模拟通过就认为原生手势已完成。
- 计数轮次与搭建状态分离，以有效轮次 / 集合身份取消过期语音。撤销记录已提交的搭建操作，不记录音频或逐帧拖动；具体状态管理库未选。
- 颜色与外形是独立属性，不从颜色推导数字，也不从占屏面积推导数量；未来几何拼片与数字单位方块使用明确的模式 / 计数单位边界。
- 支持平台、系统版本、屏幕方向、手势方式、音频与存储方案，在 PRD 收敛后确定。
- 全屏、动态视口和主屏幕显示等浏览器能力放在 Web 适配层，不让共享数学逻辑直接依赖 `document` / `window`。
- 数学状态与语言资源分离；同一语义键对应中英文案和音频，切换语言不能重新创建玩法状态。具体本地化库与语音制作工具暂不选型。
- 首轮网页需要静态资源托管，但不要求业务后台、账号、云构建或商店发布；托管平台、域名与正式发布需另行确认。

## 9. 隐私与首版非目标

建议默认：核心玩法不依赖在线业务后台，无账号、无广告、不收集或上传儿童个人信息，不接入第三方行为分析。网页首次加载仍访问资源服务器；托管可能产生基础请求日志，未来发布前需检查日志、第三方资源与隐私说明。是否保存本地设置，以及网页离线缓存范围，需单独确认。

首版不做：

- 内购、订阅、支付、商店运营和增长投放。
- 联机、多用户社交、聊天、排行榜。
- 开放式 AI 对话、在线实时生成儿童内容。
- 摄像头、麦克风、定位或儿童照片 / 声音上传。
- 大型内容后台、云同步、复杂学习报告。
- 3D、复杂物理系统、完整关卡编辑器。
- 一次性覆盖澳洲学前及小学所有学科。

未来商业化前，应另行开展儿童隐私、素材许可和商店合规审查；本草案不能替代法律或平台审核。

## 10. 首轮验证计划

由家长陪同，以短时、可随时停止的试玩观察为主，记录尽量不包含儿童可识别信息，不上传视频或声音。

重点观察：

1. 是否理解点数与拖动，哪一步需要家长反复解释。
2. 是否主动重试、改变排列，或发现提示之外的操作。
3. 能否表达当前数量，是否反复数同一块。
4. 抓取是否跟手，吸附是否宽容，能否不经家长代做直接取出 / 拼接 / 拆下 / 收回。
5. 能否在真实积木中尝试类似数量操作。
6. 开放重排 / 配色后，是否主动创造新摆法；是否误以为长条更长就一定块数更多，或换色后数量变了。
7. 后续引入形状、分类或规律时，是否理解当前目标，而不是只记住一个固定模板。
8. 是否能把数字与个数联系，而不是只认颜色；换排列是否仍表达相同总量；第二阶段是否理解两组具体数量的合体，而非背算式。

记录模板：日期、活动、家长帮助程度、主动探索例子、卡住的位置、下次要修改的一个问题。

观察孩子的自发操作与家长代操作要分开记录。App 自动报对数字不是理解的证据；可邀请用现实物体再试同一动作，但不把一次成功当作达标。继续扩展前先修复数值错误与主要触摸障碍，之后每次只增加一类内容。

这是可用性与探索行为观察，不是认知提升的实验结论。不以使用时长、连续登录天数或闯关数量作为首轮成功标准。

## 11. 里程碑

| 阶段 | 产物 | 开始下一阶段的条件 |
|---|---|---|
| M0：需求澄清 | 确认事项与可验证假设、手机 / 浏览器、双语和数据边界 | 持续澄清，可与玩法设计并行 |
| M1：PRD 收敛 | 数字伙伴美术、第一阶段数字 / 个数 / 形状对应与第二阶段加法规划 | 先让学习主轴与手感一致，不把物理实验当首要内容 |
| M2：第一阶段原型 | React Native Web 工程、数字与个数匹配、真实拖放、双语与渐进全屏 | 真机可理解并操作，数量对应及取消恢复一致 |
| M3：家庭验证 | 家长观察记录、交互问题清单 | 能理解玩法，主要操作障碍已解决 |
| M4：第二阶段与扩展 | 加法伙伴合体，之后另评规律 / 几何 / 数域扩展 | 具体集合与算式一致，按观察结果逐项增加 |
| M5：商业化评估 | 发布、权利、隐私及收费方案 | 核心体验已验证；另行批准 |

目前处于 M1：已做真实拖放判题的四站闭环和 3+4 样例，但仍是独立会话原型，不是 React Native 工程。正式音频、真机和儿童试玩未完成，未达到 M2 的工程验收条件。

## 12. 优先待确认的问题

先收敛真正影响首个体验的三个选择，不把所有问题都当作头脑风暴的前置门槛：

1. 评审已确认的章节 / 单题 / 地图 / Boss 路线：普通题数量、Boss 频率、下一站转场，保留已认可的 UI 与拖放。
2. 数域与题库：6、9、17 示例如何进入首章？17 是否可选、如何提供大数支持？第二章指定加法与自由合成、和的上限、组合握把及双语待收敛。
3. 首次试玩条件：具体手机 / 浏览器是什么，两种语言通常更熟悉哪种？孩子现有点数与触摸经验会帮助挑选起始体验，不用于设能力等级。

其余问题继续保留，但按需要决定：

- 画草图可以先尝试竖屏布局，但方向未确认，不强制锁屏；真机测试前明确目标设备和横竖屏适配。
- 家长切换、一次播一种语言是建议；默认语言、中文音种、英语口音和语音制作需在音频制作前确定。
- 无账号 / 广告 / 上传 / 付费是首轮建议边界，不默认授权部署、接入服务或商业发布；离线缓存与刷新恢复单独决定。
- 所在州 / 学校体系及正式课程映射深度待确认，不能按执行环境所在地推断。
- 本地作品墙、额外主题、内容后台、商店和收费都不是当前必须决定的事项。

确认后更新本 PRD，并同步 [讨论与决策记录](discussion-and-decisions.md)。
