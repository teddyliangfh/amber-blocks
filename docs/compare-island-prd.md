## 0. 一页摘要

- **Ted 的反馈（2026-10-27）**：不接受 v11 的比一比岛（工作台上方一条"比较台"，孩子在下面搭一排或挑一个伙伴去"比它多 / 少 / 一样多"）。他要的是：**屏幕上左右两个数字，各带自己的方块；孩子拖一个 `>` `<` `=` 放进中间的空格来答题。**
- **四个已定的取舍**：纯符号（女儿已经认识 > < =，不画鳄鱼嘴），但符号块要醒目、可爱；拖符号进中间空格是主路径，点一下符号它也会自己飞进去；全岛只选符号，不再有动手改方块的站；旧比一比岛的记录清掉，从新岛第 1 站重新玩。
- **一站 = 几轮**：每站 3 轮（Boss 4 – 5 轮），一轮是一对数。答对一轮小庆祝，下一对滑进来；最后一轮答对才过关。
- **难度不靠"动手"，靠旋钮**：数的大小（≤ 5 → 6 – 9）、两数差多少（差很多 → 差 1 → 一样多）、可选的符号（先只有 `>` `<`，再加 `=`）、方块的摆法（站着的塔、躺着的一排、方块；"4 躺着还是 4"）、一边由两个伙伴组成（"2 和 1 也是 3"）、轮数。
- **答错不是错**：放错的符号摇摇头、飘回托盘，卡片用琥珀色说出事实（"4 比 1 多"）、建议换一个符号；没有红叉、没有失败音。求助三级：重说并逐块亮数 → 说出哪边多 → 点名符号、示范手搬过去。
- **工程**：一种新的站（左右两边是展示，不是材料），内容版本 12，比一比岛换成新的岛 id（旧 ch4 退役），存档格式不变；旧 v11 的比较台代码不再有用就删掉。实现在新会话里做，先出界面设计稿给 Ted 看，再写代码。

## 1. 背景与已定的决定

### 1.1 为什么重做

v11 的比一比岛把"比较"做成了一个搭建动作（D-122 – D-128）：比较台站着对面的伙伴，孩子在下面搭一排。设计稿当时的原则是"答案就是动作，不出现选 > < = 的按钮"（设计稿 §1.2）。Ted 试玩后否定了这个形式：他的女儿已经认识 > < =，他想要的是**看两个数、选符号**这种更直接的比较题，而方块是帮孩子看出"哪边多"的依据。

### 1.2 Ted 的四个回答（2026-10-27，D-129）

| 问题 | 决定 |
|---|---|
| 符号长什么样 | 纯符号 `>` `<` `=`，不用鳄鱼嘴；符号块要做得醒目、可爱 |
| 怎么作答 | 拖符号进中间空格；点一下符号也会飞进去 |
| 要不要动手改方块的站 | 不要，全岛只选符号 |
| 旧比一比岛的记录 | 清掉，地图停在新岛第 1 站；其他岛的记录全保留 |

### 1.3 和全局原则的关系

- PRD §5.3"主路径只有抓取、移动、松手"：符号块仍然是**拖**进空格（主路径），"点一下飞进去"是 Ted 认可的例外（手小、拖不准时不卡住）。只在比一比岛的符号块上生效，其他岛不变。
- 设计稿 §1.2"不出现选 > < = 的按钮"：被 D-129 推翻（只对比一比岛）。符号不是按钮，是可以拖的块，长相和积木一个家族。
- 不变：不自动语音（新句子在点按时说）；不扣分、不倒计时；没有红叉和失败音；颜色不是唯一线索；每站一个自然结束点。

## 2. 目标与成功标准

**怎样才算成功**（让孩子试玩时看，见第 9 节）：

1. 孩子不用大人解释，看见"左边 4、右边 1、中间一个空格、下面三个符号"就知道要把符号放进空格。
2. 第一次放进去就能读出方向（"4 > 1"），放错后看了卡片、数了方块能自己改对，而不是三个符号挨个试。
3. 摆法不同时（站着的 3 比方块的 4 高）会去数或看数字，而不是只比高矮。
4. 一站 3 轮不嫌长；Boss 5 轮还愿意玩完。

**学的是什么**：把"哪边多"和符号的方向连起来；`=` 表示一样多；同一个数换个摆法还是那个数；几个伙伴合起来的数也能比。**不学**：符号的名字以外的读法、三个以上的数排序、"多几个"。

## 3. 玩法

### 3.1 一轮怎么玩

1. 舞台上左右各一个"数字伙伴"：上面一块大数字牌（如 `4`），下面是它的方块（默认站成一座塔，第一块有脸，颜色是这个数的颜色）。两个伙伴中间是一个**空格**（虚线圆角框，轻轻呼吸，提示"放这里"）。
2. 舞台下方的托盘里放着可选的符号块（第 1 站只有 `>` `<`，第 2 站起三个都有）。
3. 孩子把一个符号块拖进空格（或点一下，它自己飞进去）。
4. **对**：符号块"咔哒"卡进空格并发亮；多的那边的伙伴跳一下、少的那边仰头看它（一样多时两个一起挥手）；云朵写出 `4 > 1`；响过关音，第二拍依次响左边、右边两个数的点数音（高→低、低→高、同音两声）。这一轮算过；不是最后一轮时，0.8 秒后这一对滑出、下一对滑进来，符号块回到托盘。
5. **错**：符号块在空格里摇摇头，飘回托盘自己的位置；卡片琥珀色说出事实（"4 比 1 多 / 3 和 3 一样多 / 2 比 5 少"），正文"换一个符号试试"；响轻轻的"嗯？"（现有 adjust 音），两边伙伴歪头。不扣分，这一轮继续。

方块只是展示：**不能拖**，但可以**点着数**（和其他岛一样，点一块亮一个数，数完"一共 n 块"）。

### 3.2 一站

- 每站有固定的几对数（关卡表），默认 3 轮，Boss 4 – 5 轮。"再玩一次"按种子洗一下轮次顺序。
- 云朵下方一排小圆点表示轮次（●●○）。
- 最后一轮答对 = 过关：完整两拍庆祝、彩纸、"下一站"。作品册存最后一轮的样子（左右两边 + 中间的符号）。
- 中途离开或刷新：重新从这一站第 1 轮开始（轮次是界面状态，不进存档）。

### 3.3 求助阶梯（点卡片 / 帮助，同 D-076 的三级）

| 级 | 说什么 | 亮什么 |
|---|---|---|
| 1 | 重说题目"4 和 1，选一个符号放进中间" | 两边的方块依次亮出 1、2、3……（只响点数音） |
| 2 | 说出关系"4 比 1 多 / 3 和 3 一样多"（同答错时的卡片句） | 多的那一边的伙伴（一样多时两边） |
| 3 | 说出关系并点名符号"4 比 1 多，用大于号" | 对的符号块；示范手把它搬进空格 |

示范手：进站 5 秒没碰屏幕时出现一次（现有规则），演示"拖一个符号进空格"，搬的是对的那个（第 1 轮）。

### 3.4 说什么、写什么

- 过关句：默认念符号名"4 大于 1 / 2 小于 5 / 3 等于 3"（`SAY_SYMBOL_NAMES = true`，Ted 说女儿认识符号）；改成 `false` 就念"4 比 1 多"。
- 卡片在答错时说"4 比 1 多"（关系），不说符号名：答错后要孩子自己把关系和符号连起来。
- 云朵答对前写 `4 □ 1`（中间一个空框），答对后写 `4 > 1`。

### 5.1 竖屏布局（375 × 812 为准）

```

```

- 两边的塔底边对齐在同一条"地面"上，空格在中间；数字牌在塔顶上方，大而清楚。
- 摆法不同的站：一排躺着的方块宽，塔窄；舞台按最宽 / 最高的那边定格子大小，左右对称。
- 横屏（667 × 331）：左侧竖栏照旧（云朵、卡片、按钮），舞台里左右两边 + 空格一行，符号托盘在舞台下方或右侧（按空间，同现有 `arrangement`）。
- 360 × 640 / 667 × 331 下"下一站"按钮、符号块都在屏内（门禁测试覆盖）。

### 5.2 符号块（Ted：醒目、可爱）

- 圆角方块（和积木同一套塑料质感：顶部高光、底部深色唇边、硬阴影），比积木大一号（≥ 64px，小屏 ≥ 56px），粗白色符号（Fredoka 700），符号下方一对小眼睛和腮红，和积木角色是一家。
- 三个符号的颜色不用数字的颜色（数字颜色已经代表 1 – 10）；默认三个都是同一种醒目的"魔法色"（琥珀 / 金色系），靠字形区分（颜色不是唯一线索）。具体色板在设计稿里用 `better-colors` 定，验对比度。
- 状态：托盘里轻轻呼吸；拿起来眼睛睁大（同积木）；进空格"咔哒"缩放回弹；对了发亮、眨眼；错了摇头（左右 ±10° 三下）后飘回；减少动效时只换色、不摇不弹。
- 空格：虚线圆角框，和符号块一样大，里面淡淡一个"?"（不是字，是形状），没放东西时每隔几秒轻轻放大一下。

### 5.3 两边的数字伙伴

- 塔：每块一格，颜色按这个数（`hueFor(n)`），最上面一块有脸（平静 → 过关时笑），塔顶上方一块数字牌。
- 两个伙伴组成的一边：上下叠成一座塔，两段各自的颜色和小徽章（2 和 1），数字牌写总数 3。
- 一排 / 方块：同一个数换个摆法，颜色、脸、数字牌都一样。

### 5.4 地图、收尾页、作品册

- 地图：比一比岛仍在拿走岛下面、最后一个，岛名"比一比岛 / Compare Island"。站点标签默认写第一轮的数和答案 `4>1`（`MAP_SIGN_LABEL = 'first-pair'`；`'signs'` 改成只写这一站能用的符号），颜色按第一轮大的那个数。
- 拿走岛收尾页"去比一比岛"；比一比岛收尾页"所有的岛都完成了！"，展示 Boss 最后一轮（两边 + 符号）；奖杯要比一比岛也打完。
- 作品册：比一比岛一组，每站一张"最后一轮"缩略图，中间画上符号。

## 7. 数据与工程（建议，实现会话可调整，但要记进决策日志）

### 7.1 站的规格

- 新 `QuestionSpec`：`{ kind: 'sign', rounds: ReadonlyArray<{ left: Side; right: Side }>, signs?: ReadonlyArray<Sign> }`，`Side = number | { n: number; layout?: 'tower' | 'row' | 'square'; parts?: ReadonlyArray<number> }`，`Sign = '>' | '<' | '='`。

## 9. 假设与试玩时看什么（都是【假设】）

- [ ] 她能不能读出符号方向（放 `>` 时是看数字、看方块还是乱放）——看第 1 站第 1 轮。
- [ ] 答错后会不会三个符号挨个试——如果会，考虑 `WRONG_SIGN = 'stay'`（错的符号留在空格里，要她自己拿出来）或答错后自动亮数。
- [ ] 点一下飞进去会不会让她不再拖——如果是，考虑关掉点按（`TAP_TO_PLACE = false`）。
- [ ] 摆法不同（矮的方块 4 对高的塔 3）她会不会被高矮骗——这一站是不是太难。
- [ ] 3 轮一站是不是太长 / 太短；Boss 5 轮会不会不耐烦。
- [ ] 念"4 大于 1"她喜不喜欢，还是"4 比 1 多"更自然。

## 10. 不做（这一轮）

- 鳄鱼嘴（Ted：直接用符号）；动手改方块的站（Ted：只选符号）。

- 只有数字没有方块的站（Ted 要求两边都有方块）；方块先藏后揭的玩法。
- 天平 / 跷跷板这种另一套比喻（可能以后当过关动画参考）。
- 随机题里的比较题（自由玩不加新题型）。
- 旧 ch4 记录的迁移保留（Ted：清掉）。
