# Amber Blocks：章节地图、关卡与 Boss

版本：v0.2  
日期：2026-10-12  
状态：章节 / 小题 / 地图进度 / 周期性 Boss，以及第二章组合积木加法，是用户明确提出的方向。以下具体关卡表、随机参数、保存和转场为设计建议，不是已完成的正式游戏或已验证课程。

关联：[PRD v0.10](prd.md)、[学习主线](learning-stages.md)、[当前可玩切片](playable-slice.md)。

## 1. 已确认的变化

- 保留目前认可的鲜明数字伙伴 UI 与真实拖放，不重新选美术风格。
- 主线从自由选数字演示变成“大章节 → 一题一个小关卡 → 过关前进”。自由拼搭可作为补充入口，不取代闯关主线。
- 地图显示已完成、当前、未到达；每几个小关卡出现一个较难的 Boss。
- 第一章认识数字 / 对应单位个数，可结合组合形状；数字不按 1、2、3 顺序机械增加。
- 用户给出的数字例子为 1、2、4、6、9 和末关 17；不是已经确定的连续关卡表或四岁达标标准。
- 第二章加法，备选区出现真实组合伙伴，如 5、4 等；选项伪随机，可完成 3 + 4 = 7。

## 2. 让前进产生可见后果

候选故事：数字小伙伴一起旅行。完成一道题，小伙伴走到下一站、脚下路径点亮；Boss 是修好一个更大的伙伴造型，不是战斗。章节结束，下一片地图打开。

一个循环：看目标 → 抓取真实块 / 伙伴 → 拼搭 → 稳定松手后判定 → 短反馈与点亮地图 → 下一题。

- 不要求额外点“提交答案”；系统依据有效提交的积木状态判断。
- 建议成功后保留作品，出现“下一站”，点击才清楚地收好当前材料并换题。过关是前进条件，不用长庆祝动画锁屏。
- 自动下一题的等待时间尚未确认，首轮建议不定时强行清空孩子正在改造的作品。
- 每一站有不同造型 / 小故事后果，但不增加无关小游戏；避免回到三个小座位的机械填孔题。
- 无扣分、生命、倒计时、排行榜、强制连续游玩；Boss 可重试、提示、回地图或结束。

## 3. 第一章候选地图：数字岛

下面是讨论用的一条样例路线，具体题数、顺序和数域待试玩；“17”先作为可选的本章终点挑战。

| 路段 | 题目例子 | 变化点 | Boss |
|---|---|---|---|
| 小伙伴出发 | 1、2、4 | 先数量，再出现清楚的 2×2 形状目标 | 3：用三块拼出转角伙伴 |
| 形状花园 | 6、4、9 | 数量不单调递增，穿插熟悉数字；长条 / 方阵 | 8：八块换成指定造型，数量仍是八 |
| 大伙伴山 | 10、7、12 | 引入更大身体；可用明确的整组握把搬运 | 17：大伙伴身体由 10、5、2 个单位拼完整 |

三道普通题一个 Boss 是首轮候选节奏，不是最终固定频率；内容配置允许每段 3–5 题。地图节点是关卡次序，题目数字是学习目标，两者必须区分。

17 的设计风险是触摸面积和重复动作，不用把 17 个块缩成难抓的小按钮，也不要求机械拖 17 次。候选方案：先展示 17 个可点数单位，提供清楚标注的 10 / 5 / 2 组合握把，孩子搬整组，再看同一批单位组成 17。此时仍是数字与具体总量，不强制第一章填写加法算式；首次出现整组操作须有示范，不暗改单块手势。

正式进入 17 前需要更大数字的认识 / 点数支持。能完成低数题不自动证明理解 17；家长可降回熟悉题或直接陪玩大伙伴。是否把 17 放在第一章主线，待实际观察后确定，不以“Boss”名义强制跨度。

## 4. 题型与判定不能混淆

| 类型 | 可见目标 | 判定 |
|---|---|---|
| quantity | 拼出 3 块 | 已提交工作区有 3 个不同单位身份；任意摆法成立 |
| quantity_shape | 用 3 块拼成这个转角 | 真实个数正确，且单位占用的相邻关系符合明确轮廓 |
| addition_exact | 把 3 和 4 合起来 | 用真实三块组和四块组合体，显示 3 + 4 = 7；5 + 2 不是本题指定动作 |
| sum_composition | 自由拼出 7 | 允许 3 + 4、5 + 2 等题目允许的组合，不暗中限定只有一种分法 |

- 轮廓是伙伴身体示意，不是每块必须精确对齐的像素答案；吸附容差独立于数学规则。
- 形状判定去除整体平移；普通题建议允许旋转。镜像是否等价由题目显式配置，示范须与判定一致。
- 只要求数量时不因颜色、连接方式或外形判错；要求形状时事先展示，不临时追加隐藏约束。
- addition_exact 可让孩子先看见两个数和具体组，结果留作合体后的揭示；数词、两个组与结果同步。若 3、4 顺序无学习意义，允许先拖四块再拖三块。
- 拖动中不判题，取消 / 无效落点不记进度；合体通过身份并集统计，不从标签 / 颜色算数。

## 5. 第二章候选地图：合体岛

现状（内容版本 7，2026-10-18 Phase 21，D-089 – D-094）：12 站，1 + 1 → 2 + 1 → 2 + 2 → 两个 5 叠成十（造型）→ ★找两个伙伴拼出 5（allowed 2 + 3 / 4 + 1）→ 送走多的（工作台上 3 + 4 + 2，送走 2 拼成 7）→ 还差谁 2 + ? = 5 → 还差谁 4 + ? = 6 → 1 + 2 + 3 搭楼梯（三个伙伴）→ 还差谁 3 + ? = 7 → 十几 10 + ? = 13 → ★7 的两种拼法（3 + 4 与 5 + 2，同一托盘，干扰 1）。每两三站换一种动作；两个 Boss 进站时有答案大小的虚线轮廓（Boss 登场）。内容版本 6 的 8 站一字未改（D-091）。

- 送走多的：开局三个伙伴已在工作台上排成一排、比和多；只有一种送法、送走后剩下的那一对仍相贴；开局算开题（卡片说题目，不是"多了 2 块"），示范手把多的那个搬回托盘。
- 三个伙伴：楼梯只认 1 / 2 / 3 一级一个伙伴；2 + 4 数量对但搭不成，帮助会说换伙伴、点名 4。

- 还差谁：开局一个伙伴已在工作台上（它是答案的一部分，可以拖回托盘，托盘里留着它的轮廓）；云朵显示和，题目"已经有 2 了，再找一个伙伴，拼成 5"；只接受 given + 另一半，换掉 given 的其他凑法（1 + 4）走"1 加 4 也是 5！再找 2 和 3"；少了不说差几块。
- 两种拼法：同一站分两步，每步接受任何一个还没用过的允许拼法；第一步是小庆祝（同数字岛 4 站的"变个样子"），工作台上还是那一对时提示"换一种拼法！"，拼出另一种才过关。
- 每站最少拖拽：还差谁 1 次（原 3 + 2 / 4 + 1 / 3 + 4 都是 2 次）；两种拼法 6 次（拼、送回、再拼）。决策：还差谁要从托盘里挑出唯一能补全的那一个（不能对号入座找题面上的数字，题面只有和）；两种拼法第二步只能用另外两个伙伴。
- 没做（Phase 20 再议）：三个伙伴合体、凑到 10 的"大合体岛"、合体瞬间"变成 n"的动画、拆开 / 拆分命令、内容池与"换一题"。（Phase 20 做了合体变身；Phase 21 做了三个伙伴的楼梯、"送走"、十几与自由玩随机题；拆开岛、"换一题"仍没做。）

原候选递进（2026-10-12，仅作历史）：1 + 1 → 2 + 1 → 2 + 2 → 小 Boss；再穿插 3 + 2、4 + 1 → 3 + 4 = 7 的章节挑战（内容版本 1–5 就是这样做的）。

备选区不再全是单块，而是可拖的完整伙伴。例如题目 3 + 4，托盘可为 [5, 3, 2, 4] 的洗牌；每个伙伴确有对应单位，数字贴在握把旁，不仅是一张数字牌。

- 普通题建议 3–4 个可抓伙伴，包含解与少量干扰项；形状可以变化，但不能把 4 块角色画成 5 块。
- 合体区接受整个组，保留来源单位与分色 / 分隔，随后显示真实总量和对应算式。
- 选错组可拖回，不扣分；“这是五块，我们先找三块和四块”是候选描述性提示。
- 当 a = b，例如 2 + 2，必须提供两个身份不同的两块组；不能复用同一伙伴计两次。
- 托盘随机顺序不能使唯一正确组永远在同一位置；干扰项也不能制造只按颜色选答案的捷径。
- 暂不增加符号键盘、填空或限时口算。

### 5b. 第三章：拿走岛（内容版本 8，2026-10-19 Phase 22，D-099 – D-104）

设计见 [take-away-and-compare-design.md](take-away-and-compare-design.md)（§3.1 的默认表照做，比一比岛留给 Phase 23）。8 站：拆 3 → 拆 4 → 拿走 4 − 1 → ★ 5 的两种拆法 → 拿走 5 − 2 → 拿走伙伴 6 − 2（4 + 2）→ 拿走伙伴 7 − 3（3 + 2 + 2）→ ★ 倒数火箭 5 → 4 → 3 → 2 → 1。一个岛只教一个新动作（拉开 / 送回家），数都 ≤ 7；减法 = 送回家（托盘就是家），拆开 = 拉开一排；core 只加 `split` 判定，拿走就是 `quantity` + 开局在工作台上。接在合体岛后面，不动任何旧站；全通的旧存档升级后落到拿走岛第一站。

## 6. 可控伪随机，而非随意出数

建议把“地图进度”和“本题参数”分开：地图的概念、Boss 节奏固定，目标 / 造型 / 托盘顺序在已定义难度带内变化。

出题步骤：按当前节点题型与数域 → 从允许目标池抽取 → 避免近两题同目标（池过小时放宽）→ 选择兼容形状 → 生成足量解材料 → 加合法干扰项 → 洗牌 → 验证可解性与屏幕容纳能力。

- 使用保存的 seed、contentVersion、nodeId、attemptVariant 生成确定结果；不是按时间不停变化，更不在线调用 AI 随机出儿童题。
- 初次进入生成一次并保存；退出 / 回来 / 切语言不重抽，重播默认同题。主动“再玩新题”才生成新变体。
- 随机范围有教学包络：早段如 1–4，中段如 4–9，更大数另有支持；不能把 1 到 17 完全无约束乱抽。
- 玩家移动积木不会改变题目。随机不增加奖励箱或随机奖品。
- quantity_shape：模板单位数必须等于目标数。quantity：库存不少于目标数，若要观察数量识别，不永远恰好给 n 个材料让全部搬完自动成立。
- addition_exact：不同组身份可满足操作数多重集；sum_composition：至少存在一个允许的组合，干扰项不能令题无解。
- contentVersion 更改后旧题仍可恢复，或明确迁移并保留完成历史；不能将旧关卡序号直接套到新内容。

## 7. 地图与进度状态

关卡状态：未到达 → 可开始 → 作答中 → 已完成；Boss 是关卡属性而不是另一套积分系统。

- completedNodeIds 是集合，同题成功多次只记录一次；地图总进度为完成节点数 / 本章节点数，不是智力分数。
- 当前关卡不是永久“失败”状态。未完成退出，回来继续原题与作品；重玩已完成关不会倒退最远进度。
- 正常路径依前一节点完成开启下一节点；章节 Boss 完成后，下一章入口出现。家长可以选择章节 / 陪玩，不把路径门槛当作年龄或能力认证。
- 保存的最小信息：内容版本、关卡与变体、已完成集合、当前稳定作品、语言。只存提交状态，不存半途拖动 / 动画 / 待播语音。
- 建议首版设备本地保存；当前预览只有会话 / 宿主状态，不代表刷新恢复、浏览器缓存、离线或云同步完成。正式存储方式待工程阶段确定。
- 本地数据清除 / 换设备可能丢进度，需家长说明；不因此默认引入登录账号 / 云服务。

## 8. 首轮交付建议与边界

先做一个真实可玩的竖切片：第一章三道普通题 + 一个 Boss + 地图 / 返回 / 重玩；第二章保留一个 3 + 4 的组合拖放样例。正式章节数域、17 Boss 与完整题库待确认后扩展。

上一轮地图草图的“预览过关”仅用于流程演示；当前另做真实拖放与判题切片，四站过关后打开 3+4 样例，无演示过关按钮。它不覆盖本章候选题表的全部内容，也不是 React Native 正式工程。

浏览器流程检查范围：第一章 12 个示例节点、第二章 8 个示例节点的顺序开启 / Boss / 重玩不重复累计；17 的示意身体与 10 / 5 / 2 材料块数一致；加法备选包含操作数，2+2 提供不同组身份，回地图不重排；3+4 的合体结果有七个单位并保留三 / 四来源分色。已检查中英切换及 320 / 390 / 736 像素明暗布局，未进行真实手机、儿童、正式手势、语音或持久存储验收。这些数量是预览示例，不是批准的课程长度。

观察重点：孩子是否期待下一站、能否理解数字与形状目标、Boss 是否多了有意义的想法而非只是更多手指动作；数量 / 加法正确性与界面状态单独自动测试。不以完成率认定学习效果。
