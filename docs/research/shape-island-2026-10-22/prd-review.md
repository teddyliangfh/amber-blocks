# 《形状玩法扩展与顶栏提示 PRD》评审（2026-10-22，只读）

评审对象：`docs/shape-island-and-header-prd.md` v0.1。方法：逐条核对五份调研与 `src/`；把 PRD 提出的 14 个 v9 / v10 站规格用真实的 `materializeNode` / `validate` / `fitBench` 跑了一遍，把 `hints.ts covers()` 原样移植后枚举了每站"伙伴 + 备用单块"的所有和为目标的组合，并用真实 `computeGeometry` 算了新旧 chrome 下 6 种视口的格 / 托盘尺寸（脚本：`scratchpad/verify-prd.ts`、`unlock-check.ts`，只读仓库）。所有站都通过 `validate()`，工作台尺寸与 PRD 一致；下面只列不成立或有疑问的。

严重度：**阻塞** = 按 PRD 写出来的站 / 测试不成立或孩子会学错；**重要** = 两个工程师会做出不同的东西、或 PRD 依赖的代码事实不对；**建议** = 数字 / 措辞。

## 阻塞

### 1. ch5-n7 小狗的"[3,2,1] 数量对铺不出"在默认可转下是假的，陷阱不存在
- **位置**：§4.1 表 DOG_6 行、§4.2.1 n7 行 + "写进目录测试：n3 / n4 / n7 / n8 的诱饵组合 … covers() 为假"、§4.2.4 `PICTURE_SYMMETRY = { rotation: true, mirror: true }`。
- **问题**：狗转 90° 后（`core/shapes.ts:24` `rotate90`，归一化后 cells = (0,0)(1,0) / (1,1) / (0,2)(1,2)(2,2)）第 0 行是 2 格、第 2 行是 3 格、中间 1 格——3 横排 + 2 横排 + 1 块正好铺满。`hints.ts:273-292` 的 `covers()` 对**所有变体**试铺，所以 3 + 2 + 1 在 n7 会被判"数量对了，再看看形状"而不是"再找对伙伴"，而且孩子真的能在影子外拼出一只侧躺的狗过关。枚举结果：`rot+mirror` 下 `3+2+1 covers=true`；`{ rotation: false, mirror: true }` 下 `covers=false`。game-design.md §1.1 第 9 行与 §3.2 的同一断言也是错的（没有试旋转）。
- **修改**：DOG_6 这一站写死 `symmetry: { rotation: false, mirror: true }`（"狗朝左朝右都是狗，不倒立"），§4.2.4 改成"有头有脚的画（鸭、狗）：镜开、**转关**；无方向的画（蘑菇、树、船、房子、火箭）：转开"。这同时保住"脸自动落在头上"（`Stage.tsx:179-181` 取最上最左，鸭 / 狗转 180° 时脸会落在尾巴上）。火箭 `[3,2,1]` 在任意对称下都铺不出，不用改。

### 2. ch5-n6"一块之差变新图 / 两步各 1 次挪动"与"影子朝向 = 模板写法、固定台中央"互相矛盾
- **位置**：§4.2.1 n6 行（"最少拖 6"、"挪一块"）、§4.2.1 末"n6 两步各 1 次挪动"、§4.2.3"影子固定在台中央、朝向 = 模板写法"、§7 假设 S3。
- **问题**：按 §4.1 的坐标，`CORNER_5`（L 形）→ `BOAT_5`（U 形）按写法只有 (0,0)(0,1) 两格重合，`solution.ts:115-122 reshape()` 的参考解是 **3 次挪动**（实跑：8 条命令、3 个 move），目录测试"各 1 次"直接红。"挪一块"只对船转 90° 的 C 形变体成立（实算：U 3 步、C 1 步、∩ 3 步、反 C 2 步）。而 n4 的 `cover()`（`solution.ts:158-183`，不试变体）又要求 `BOAT_5` 按"3 横排在底"的 U 形写。影子若按写法画 U 并重新居中，第二步影子和孩子台上的 L 既不同向也不同位，孩子要么推倒重来（S3 想避免的事），要么拼出判定通过但影子不亮的 C。
- **修改**：(a) n6 用单独常量 `BOAT_5_C = rotate90(BOAT_5)`（判定等价，指纹不同），n4 继续用 U 形 `BOAT_5`；(b) §4.2.3 加一句"序列第二步的影子以第一步**已拼成的簇的左上格**为原点画，不重新居中"；(c) 目录测试改成"n6 两步 `reshape` 各 1 条 move（按写法坐标）"。改完 CORNER_5(L) → BOAT_5_C 正好 1 步（(2,2) → (1,0)）。

## 重要

### 3. 升级 / 解锁断言与 `migrate.ts` / `unlock.ts` 不符："合体岛做到一半 → ch5-n1"是假的
- **位置**：§4.2.2"合体岛没开始的存档要先过造型岛 … 升级后 current 落到 ch5-n1"、§4.2.7 progress 行"合体岛做到一半 → ch5-n1 且旧完成保留"、§2.4 分歧表"迁移都能落到新岛第 1 站"。
- **证据**：`progress/migrate.ts:146` `onwardFrom` 对**没完成**的 `current` 原样返回；`unlock.ts:29` `current === nodeId` 永远开着，之后按前一站解锁。实跑（ch5 插在 ch1 后）：完成 ch1 + ch2-n1..n3、`current = ch2-n9`（未完成，"下一站"之后的常态）→ 升级后 `current` 仍是 ch2-n9，ch2-n9 与 ch5-n1 **同时**开着，合体岛照常往下走；只有 `current` 停在**已完成**站（孩子重玩过又离开）才落到 ch5-n1；刚打完数字岛、`current = ch2-n1` 未完成 → 留在 ch2-n1，完成后 ch2-n2 照开，造型岛永远不是必经。
- **修改**：§4.2.7 测试改成三条：① current 在未完成的合体岛站 → 不动、该站与 ch5-n1 都开；② current 在已完成站 → ch5-n1；③ 全通 → ch5-n1。§4.2.2 删掉"要先过造型岛"，改成"合体岛中途的孩子不受影响；是否强制先玩造型岛是另一个决定"，并在 §8 加一行 `SHAPE_ISLAND_GATE: 'none' | 'before-join'`（默认 none）。顺带：§8 #7 选 after-ch1 的理由"合体岛的十、楼梯变成回声"对中途存档不成立。

### 4. "每个诱饵组合 covers 为假"按字面必失败：每个握把站托盘里都有 ≥ 1 块备用单块
- **位置**：§4.1"诱饵按目录测试定（… 数量 = 目标但 covers() 为假）"、§4.2.1 末、§4.2.7 validate 行"每个诱饵组合 covers 为假"、§2.3"不混单块"。
- **证据**：`validate.ts:264` 要求 `extra ≥ 1`，`material.ts:91` 把 `target − sum + extra` 发成单块（握把和 = 目标时就是 `extra` 块）。枚举：n1 `2+1+1单块=4` 可铺、n3 `2+1+1+1单块=5` 可铺、n4 同、n5 `3+2+1+1单块=7` 可铺、n7 / n8 `2+1+1+1+1单块=6` 可铺、RING_8 `3+2+1+1+1单块=8` 可铺。只有"纯伙伴且含诱饵"的组合（n3 `3+2`、n4 `3+2` / `4+1`、n8 `3+2+1`、RING `3+3+2`、STAIRS 含 5、TEN 含 3）铺不出。n1 蘑菇的诱饵 2 根本不构成铺不出（只有 `3+2=5` 数量错），"第一次'再找对伙伴'"在 n3 才可能发生、且只对 `3+2` 这一条路。
- **修改**：测试口径写成"**仅由伙伴组成**、含至少一个诱饵、和 = 目标的组合，`covers(shapes, 0)` 为假"；§2.3"不混单块"改成"握把和 = 目标；托盘另有 `extra ≥ 1` 块备用单块，可参与拼图"；§7 的 S2 补一句"用 2 + 1 + 1 + 单块拼出也算对（4 件），记下但不算错路"。
