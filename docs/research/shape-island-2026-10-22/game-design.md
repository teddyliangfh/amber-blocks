# Amber Blocks · 形状题扩充与"造型岛"概念发散（2026-10-22）

视角：学前学习游戏设计（Numberblocks / Osmo Tangram / 图案积木都熟），先发散后收敛。只读仓库，没改任何文件。起点是 2026-10-22 的试玩反馈：**形状题太少，孩子最爱**；Ted 在想 (a) 扩基本造型集 (b) 做一个七巧板味的"形状岛"。

## 0. 先核对引擎能做什么（全部查过代码）

1. 造型题 = `quantity_shape`：数量相等 + 工作台上**恰好一簇**（边相邻）+ 整簇与模板在 `symmetry` 下同形（`src/core/judge.ts:98–108`，簇见 `src/core/clusters.ts:13`）。默认**可转不可镜**（`src/core/shapes.ts:17`），每站可自己给 `symmetry`（`src/content/schema.ts:46`）。
2. 模板就是一组格子，任何多连方块都能写（`src/core/shapes.ts:19–21`）；模板池多于一个时按种子抽一个，`sequence: true` 时按顺序全做（`src/content/generate.ts:57–75`）。
3. 伙伴身体固定是"一排 ≤ 5、6–10 两排"（`src/content/material.ts:12–24`），**孩子不能转伙伴**（`src/screens/hints.ts:269`）。用伙伴拼造型时握把必须**正好等于**目标、至少一个诱饵、不混单块（`src/content/validate.ts:276–286`）；参考解把伙伴**原样、按模板写法的朝向**铺进去（`src/content/solution.ts:158–181` 不试旋转变体）→ 用伙伴拼的模板要按"横排能铺满"的朝向写。
4. 单块造型是 `looseMaterial`（目标 + extra 块），仓库自定的规矩是**每站单块拖拽 ≤ 6**（`chapter-1.ts:82–83`）；序列站（同量变身）只对单块成立（`solution.ts:289` 只跟踪 `take` 命令）。
5. 工作台按材料定尺寸：所有对称变体的外框 + 1 圈余量 + "一排 n"永远放得下（`src/content/bench.ts:61–69, 140–154`）；可转的长条会把台子撑成正方形（十的 6 × 6 教训，D-090）；≤ 9 列（D-091）。
6. 求助阶梯对造型题现成：数量 → `countHint`；数量对、形状不对且"挪一挪能成" → "数量对了，再看看形状"+ 点亮小图；伙伴根本铺不出 → "换个伙伴试试看"（`hints.ts:258–266, 446–454, 517–556`；文案 `copy.ts:72, 84–85, 123`）。小图在云朵旁（`src/screens/LevelScreen.tsx:619–656`）。
7. 随机骰子自动收录**已完成的造型站**的每张图（含握把 / 诱饵）（`src/content/challenge.ts:102–125`）；作品册按站自动出现；地图标签 = 目标数（`src/screens/MapScreen.tsx:66–67`）；Boss 虚线轮廓只会画"一排 n"（`src/blocks-ui/BossOutline.tsx:16–31`），是纯布景。
8. 脸在一簇的最上最左那块（`src/blocks-ui/Stage.tsx:179–181`，作品册同 `picture.ts:21–23`）；簇色 `hueFor` 封顶 10（`material.ts:7–9`）。过关动作按数字查表，Boss 特例 car / tall-wave / launch（`src/blocks-ui/cheer.ts:6–39`）。
9. 内容版本 8（`src/content/catalog/index.ts:14`），Phase 21 / 22 的做法：新 id 插进地图顺序、旧站一字不改、`CONTENT_CHANGES[9] = []`、全通存档升级后落到第一个新站（`src/progress/migrate.ts:139`）。
10. PRD 红线：几何拼片（三角形等）**不能**和计数方块共用数值语义；若播报数量只能说"用了几块拼片"（`docs/prd.md` §4.5）。

一句话：**单位方块网格内的任何造型，今天的引擎一行不改就能出题**；三角形 / 自由画布 / 三角网格都要动 core。

## Part 2 · 形状岛的五个发散方向

共同约束：一岛一动作、数 ≤ 7、先做后看记法、无红叉、三级求助、不识字、拖放主路径、块是角色、数 = 真实单位数、要进作品册 / 沙盒 / 骰子 / 收尾页、版本迁移、可测。

### (i) 影子剧场 · 方格拼画 / Shadow Theatre (grid picture puzzles)

- **假设**：七巧板最核心的乐趣是"轮廓给了、挑哪块填哪里"，不是斜边；在方格里用伙伴（1–5 的横排）+ 单块就能给出这个乐趣，而且块还是数字角色。
- **机制**：工作台上躺着一张虚线**影子**（模板格子，用 `BossOutline` 改成按模板画）；托盘里是几个伙伴 + 诱饵；孩子把伙伴拖进影子，填满就亮灯变成一个角色（现有合体变身）。判定原样 `quantity_shape`——影子是布景，判定只看簇。
- **教**：部分—整体、空间关系（头在上、腿在下）、按形状挑块、"数量对但形状不对"的区分。
- **数的联系**：云朵仍是 `6` + 小图；过关念"3、1、1 和 1，一共 6 块"（现成 `feedback.matched.parts.4`）；整幅画合体成一个 6 的角色。可选 `3 + 1 + 1 + 1 = 6`。
- **取舍**：画只能是方格剪影，"像不像"靠名字和脸；放弃斜边。
- **四岁最大风险**：影子太好填，变成描红；去掉影子又回到"照着小图摆"（评审第七轮批评过的空阶梯）。解法：影子是机制（七巧板本来就给轮廓），难度来自**挑块**（诱饵、陷阱、件数）而不是去掉影子；只在 Boss 去掉影子、求助第 2 下再浮现。
- **引擎改动 M**：影子组件（按格子、逐格亮）、`cheerFor` 按图选动作、地图小图标签、hints 加"影子还没填满 / 伸出影子了"的点亮、目录 + 文案 + v9。core 不动。
- **状态清单**
  - 开局 / 空态：影子呼吸、第一格一张睡脸（同 Boss 登场）；云朵 `5` + 小鸭小图；卡片 ✦"动手试试看 / 把伙伴放进影子里"；5 秒没动示范手搬最大的伙伴进影子。
  - 首次流程：拖 4 进影子 → 4 格亮、睡脸醒一半（蓝色"影子还没填满 / 还差这里"，点亮空着的格）→ 拖 1 到头 → 一簇 5，第一拍"对了"音、笑脸、绿卡"小鸭拼好了！"；0.6 秒后彩纸、鸭子摇摆、合体成一个 5 的角色、"下一站"。
  - 错路 1 伙伴放在影子外 → 琥珀"伸出影子了 / 把它挪进影子里"（点亮它和空格；第 2 下"把 4 挪进影子"，第 3 下示范手挪）。若在影子外拼对了整幅 → 照样过关（判定平移不变），卡片不骂。
  - 错路 2 拿了诱饵 2（4 + 2 = 6）→ 现成"多了 1 块 / 把 2 送回去，换 1 过来"阶梯（`hint.swap.pair`）。
  - 错路 3 数量对、铺不出（小树 3 + 2）→ 琥珀"数量够了，再找对伙伴"（现成），第 2 下"把 2 送回去"（点亮 2 和影子里它盖不住的格），第 3 下完整句。
  - 错路 4 两块分开 → "再接起来"，点亮散的那块（现成 `not-one-cluster`）。
  - 等待：拖动中不判；过关后再摸影子不回来，"下一站"照常（第七轮 L2 的规矩）。

### (ii) 半方格三角 · 切一刀岛 / Half-Square Island (45° family on the grid)

- **假设**：把单位方块沿对角线切成两个直角三角形，就得到一个"网格七巧板"家族——小三角（½）、方块（1）、平行四边形（两小三角拼，1）、中三角（两小三角拼腰，1）——四岁能在同一张格子上拼出有斜边的房子、帆船、鱼。
- **机制**：拖片进影子；**旋转怎么办**：三种候选——① 按站**预先摆好朝向**发牌（像伙伴身体固定，每站托盘里的三角就是影子需要的朝向），② 落进影子格时**自动转向**（贴合那格缺的半边，0.2 秒转一下），③ 工作台上**点一下转 90°**。建议 ①+② 为默认、③ 只在后半岛作为本岛"唯一新动作"（`TRIANGLE_TURN = 'tap'`），前 4 站先不需要转。
- **教**：斜边、"两个三角 = 一个方块"（面积等价）、朝向。
- **数的联系**：**弱而危险**——半块不是一个单位。PRD §4.5 明令拼片不能用方块的数值语义：云朵只能说"用了 4 块拼片"，不能有数字角色、徽章、簇色。
- **取舍**：换来斜边，丢掉整套角色系统（脸、色、合体、作品册的 `picture.ts`）。
- **四岁最大风险**：朝向——四个朝向的三角对四岁是真难（Osmo Tangram 最低档也给预摆好的轮廓和颜色提示，目标 5+）；加上片小（半格）、指尖遮住。
- **引擎改动 XL**：`BenchState.bench` 要从"格子"变"格子 + 半边"，簇、相邻、判定、吸附、绘制、作品册、沙盒全部要分叉；等于第二套 core。
- **状态清单（简）**：开局影子 + 预摆好朝向的拼片；首次流程 = 填影子；错路：朝向反 → "转一转"（点亮那片 + 影子里的斜边方向）；平行四边形镜像（它有手性）→ 预发两种或允许自动翻；等待：旋转动画中不判。

### (iii) 真七巧板 · 自由画布 / True 7-piece Tangram (free canvas)

- **假设**：经典七片在自由画布上拼轮廓。
- **机制**：拖 + 双指转（或转盘）+ 平行四边形翻面；判定 = 七片的并集与目标多边形在容差内重合，或每片对齐到某个参考解的位姿（允许对称解）。
- **教**：旋转、面积分解、几何直觉。
- **数的联系**：只剩"7 片"。
- **取舍**：最像七巧板，最不像这款游戏。
- **四岁最大风险**：旋转 + 翻面 + 精确对齐在 375 px 手机上远超四岁（七巧板通常 5–6 岁起）；容差判定对孩子像"随机"——拼得对却不亮，违反"确定、可测、只说动作"。
- **引擎改动 XL**：全新几何核、全新手势、全新渲染；bench / clusters / judge / album / sandbox / challenge 全不复用。
- **状态清单（简）**：开局轮廓 + 七片散落；流程 = 一片片放；错路：差一点点 → 吸附；朝向错 → "转一转"（点亮那片）；翻面 → "翻过来"；等待：旋转中不判；放不下弹回。

### (iv) 蜂巢岛 · 图案积木 / Honeycomb Island (pattern blocks, triangular lattice)

- **假设**：六边形 = 6 三角 = 3 菱形 = 2 梯形，是最漂亮的"等量不同形"教材。
- **机制**：三角网格上拖拼片进影子；转 60°（点一下）。
- **教**：等价分解、对称、花样。
- **数的联系**：**有意思**——以小三角为单位，六边形是 6、梯形 3、菱形 2、三角 1，"数 = 单位数"居然成立；但这是**另一个单位**，刚学会方块单位的四岁会混，PRD §4.5 也要求分开说"几块拼片"。
- **取舍**：最美，也最像一款新游戏。
- **四岁最大风险**：六个朝向、片小、拼花容易"随便拼都好看"→ 没有过关动机（反而适合沙盒）。
- **引擎改动 XL**：三角坐标、吸附、绘制、判定全新。
- **状态清单（简）**：开局六边形影子；流程 = 两个梯形填满；错路：菱形放歪 → "转一转"；三个三角 + 一个梯形也对（多解按 multiset 承认，像"两种拼法"）；等待：转动中不判。

### (v) 镜子岛 · 对称与翻倍 / Mirror Island (symmetry = doubles)

- **假设**：对称是四岁最早能感受的几何关系（蝴蝶、脸）；而且"左右一样"= **翻倍**（3 + 3 = 6），是数字内容里最自然的几何入口。
- **机制**：工作台中间一条镜线；左半边**开局已摆好**（像拿走岛的 `presetMaterial`，是真材料、可动，但卡片说"左边是它的"），右半边有淡影子（左半的镜像，`mirrorX` 现成）；孩子从托盘拼右半边。判定：`quantity_shape` 用**整幅对称模板**，一行不加（左半 + 右半是一簇 → 整簇同形）。
- **教**：对称、"一样多"、翻倍。
- **数的联系**：强——云朵 `3 + 3 = 6`、`4 + 4 = 8`、`5 + 5 = 10`（和合体岛"两个 5 叠成十"直接接上）。
- **取舍**：图只能是左右对称的（蝴蝶、脸、城堡）；镜线要占一列。
- **四岁最大风险**：四岁会"平移复制"不会"镜像复制"（把左边的形状原样搬到右边）；没有影子几乎不可能，有影子又是描红。缓解：前几站影子常亮、后几站影子只在求助时浮现；"平移复制"的错路要有专门的话："翅膀要朝外 / 像照镜子"。
- **引擎改动 M**：镜线布景、左半预置（复用 `presetMaterial` 思路但按格子摆）、影子组件（与 (i) 共用）、文案；core 不动。
- **状态清单**：开局左半蝴蝶翅膀（3 块）+ 镜线 + 右半影子、云朵 `3 + ?`；流程：3 块填进右半 → 一簇 6 对称 → `3 + 3 = 6`、蝴蝶扇翅；错路：右半平移复制（翅膀朝里）→ 琥珀"要像照镜子 / 把这块挪到最外边"（点亮镜像格）；动了左半 → 蓝色"左边是它的，先放回去"；多放 → "多了 1 块"；等待：影子浮现动画中不判。

### 五个方向一眼看

| | 新动作 | 数的联系 | 四岁可做 | 引擎 | 复用角色系统 |
|---|---|---|---|---|---|
| (i) 影子剧场 | 挑块填影子 | 强（块数、合体、parts 句） | 高 | M | 全部 |
| (ii) 半方三角 | 转 | 弱（只能说"几块拼片"） | 中低 | XL | 无 |
| (iii) 真七巧板 | 转 + 翻 | 无 | 低 | XL | 无 |
| (iv) 蜂巢 | 转 60° | 另一套单位 | 中低 | XL | 无 |
| (v) 镜子 | 照镜子摆 | 强（翻倍） | 中 | M | 全部 |

## Part 3 · 收敛：推荐 + 8 站草案

### 3.1 推荐

**分两步：先 Part 1(a) 的 6 站快赢（内容 v9，半天），再做方向 (i) 影子剧场作为"造型岛 / Shape Island"（内容 v10，2–3 天），(v) 镜子的"翻倍"留给以后的第 6 岛。** 对照原则：

1. 一岛一动作：新动作只有一个——"挑合适的伙伴填进影子"；拖放、伙伴、诱饵、合体全是旧的。
2. 数 ≤ 7、难度来自选择：8 站全部 4–7 块，旋钮拧的是件数（2 → 4）、诱饵相似度（1 个 → 2 个 → 数量对却铺不出）、步骤（变身站）、支架（Boss 无影子）。
3. 先做后看：云朵过关前只有数 + 小图；过关后念"3、1、1 和 1，一共 6 块"，整幅画合体成一个角色，记法可选。
4. 不改判定、不改存档：`quantity_shape` 原样，影子是和 Boss 轮廓一样的"只画不算"的东西；作品册、骰子、收尾页零改动就接上。
5. 可测：影子格、点亮集合、阶梯三级都是纯函数（hints.ts 已是这种写法），每站的陷阱写进目录测试（像 ch3 的"n7 送走两个 2 剩 3 块"）。

不选 (ii)(iii)(iv)：它们都要第二套 core 且违反 PRD §4.5 的单位红线；留作"孩子 5 岁以后"的备案。

### 3.5 庆祝、作品册、沙盒、骰子、收尾页、Boss

- 过关动作：`cheerFor` 加可选 `picture`：mushroom → hop，duck → wiggle，tree → wiggle，boat → wiggle（左右摇），house → 脸眨眼 + 徽章（复用 `stand`），dog → hop，rocket → **launch**（现成）。n4 小船 Boss 用 `wave`。两拍规则不变。
- 作品册：零改动，每站存最新一次拼对的台；整幅画是一个角色（`picture.ts` 簇规则）。
- 骰子：零改动——完成的造型站自动入池（含握把 / 诱饵）；影子按站规格画（随机题走关卡同一屏）。可选 `CHALLENGE_SHADOW = 'as-stop'`。

### 3.7 不做清单

- 三角形 / 半方格 / 真七巧板 / 图案积木：要第二套 core，违反 PRD §4.5 单位红线，四岁的旋转负担太重。
- 让孩子转伙伴（点一下转 90°）：伙伴身体是身份（每个 4 长得一样），转了就不是"4"；影子已经把朝向定了。
- 自由画布、容差判定：不确定、不可测。
- 用伙伴做"同量变身"序列：参考解只支持单块（`solution.ts:289`）；要做得先改 `reshape`。
- 8 块以上的画进造型岛：数 ≤ 7；甜甜圈 8、大方块 9、站着的十、大楼梯 10 放数字岛 / 合体岛插站（Part 1）。
- 影子吸附 / 影子判定：影子是布景，判定仍是平移不变的簇匹配，否则在影子外拼对会"错"。
- 新的自动语音、计时、分数：照旧不做。
