# 顶栏提示（云朵数字 / 形状小图 / 提示卡）UX 审计与方案

日期 2026-10-22 · 触发：Ted 看孩子玩后的观察「顶栏的数字、形状、提示都太小、不够抓眼」。
范围：`LevelScreen` 固定顶栏 + 提示卡。只读审计，数字全部来自代码与 `layout.ts` 实算（脚本 `scratchpad/geo.ts`、`geo2.ts`、`contrast.py`），不是估的。

## 0. 一句话结论

**不是字太小，是「牌子」不显眼。** 数字本身 62px 已接近积木高度；真正的问题是：白云 / 白卡在 `#CFE9F7` 天空上只有 1.19–1.26:1 的对比，没有脸、没有饱和色、开站时不动，而工作台上的积木有脸、有饱和色、会动、还在手指下。形状小图更是「整个答案比一块积木还小」（48px 对 62px）。所以先做 **C（开场仪式，零预算）+ A-lite（小图并入云朵、上色加脸，顶栏只加 16px）**，B（目标幽灵搬上工作台）留给形状 / 比较岛。

### 1.3 为什么 4 岁孩子看不见它——尺寸问题 vs 显著性问题

**尺寸（真的小）**
1. **小图整体 48px < 一块积木 62–74px。** 「要拼成什么」的图比「一块材料」还小，每格 18px 是积木的 1/3.4（面积 1/12）。2026-10-16 复审把它从 11 放到 20 后结论仍是「仍是云朵旁小框」（`full-review-2026-10-16.md:386,404`），说明再放 1.8 倍不够，是量级问题。
2. 算式站（Take-away 岛全岛、ch2 加法）数字缩到 44 / 30px（`:1009-1012`），字形只有 21–31px，比单字站小一半，而这些站恰恰是任务最抽象的。
3. 紧凑屏一律 ×0.8（`Cloud.tsx:10`）、字 48，但积木在 360×640 并没缩（67 vs 70），云朵相对积木更小。

**显著性（不小，但不抓眼）——这是主因**
4. **容器对比 1.19–1.26:1。** 云、小图盒、提示卡三个白色圆角形叠在 `#CFE9F7` 上，构成一片「低频白区」；孩子的注意力被高对比、高饱和、有脸的东西拉走，而那些全在工作台上。
5. **开站时顶栏一动不动。** `usePop`（`juice.ts:158-170`，1.32× 弹一下）只在过关和数完触发（`LevelScreen.tsx:214-215`）；开站只有 Amber 1.5px 的慢浮（`useBob(true,1.5,2600)`，`AmberGuide.tsx:16`）。工作台的积木会眨眼、拖动时抬起、示范手会动——运动在哪，眼睛在哪。
6. **小图是「图标」，积木是「角色」。** 小图是四个无脸平色方格；积木有脸、腮红、高光、投影。对 4 岁孩子，它们不属于同一类东西，不会把 48px 的图标理解为「右边那些伙伴要变成的样子」。
7. **云和小图是两个分离的小物件。** 「4」和「方阵」并排各占一框，中间 16px 空隙；任务「拼 4 个成方阵」被拆成两个符号，要孩子自己合并。
8. **位置：离手 300–450px。** 工作台在 y≈280–560，顶栏在 y 0–104；玩的时候视线根本不经过顶栏（play-review 早就提出「把轮廓放到工作台附近」，`play-review-2026-10-14.md:55-57`，至今未做，`full-review-2026-10-16.md:404` #4「部分」）。
9. **竞争者：** Amber（48px、有脸、会动、就在云的左边）和菜单圆钮（48px、右上、有边）两个「角色级」物件夹着云，云是中间最没特征的那个。Amber 本意是「话是她说的」，副作用是她比任务更像主角。
10. **提示卡文字多。** 两行（标题 + 详情）对预读者是噪音，卡上唯一能「看懂」的是 44px 图标盘，而 `✦`（开始）对孩子没有语义，灯泡要教过才懂（`AnswerFeedback.tsx:15`）。

小结：#1–#3 是尺寸，#4–#10 是显著性；只放大不改 4/5/6/7 不会解决「不抓眼」。

### 1.4 顶栏每 1px 对积木的代价（`layout.ts` 实算）

`computeGeometry`（`layout.ts:109-157`）先按宽度取最大格（`frameFor :57-78`），只有托盘放不下 ≥ 40px 的积木（`TRAY_MIN_BLOCK`，`:39`）时才被高度卡住。结果：

| 视口 | 顶栏 +16 | +24 | +36 | −8 |
|---|---|---|---|---|
| 375×812 | 9 个代表站全部 0 代价（格不变）| ch1-n8 托盘积木 58→52；ch1-n12（17）格 58→56 | 17：58→55、托盘 46→40 | 17 托盘 46→48 |
| 360×640 | ch1-n4 托盘 67→58；17 格 43→40 | 17 格 →38 | 17 格 →37 | 17 格 →45 |
| **360×568（Android 带地址栏）** | **17 格 34→32 = `MIN_PLAYABLE` 下限**（`layout.test.ts:260,271`）| 32 | 32 | 35 |
| 375×553（SE）| ch1-n4 托盘 56→40；17 保持 34 | 17 仍 34，ch1-n4 格 84→81 | 17 → 33，`layout.test.ts:179` 「17 keeps 34px」**挂** | — |
| 667×331 | 侧栏不改宽则 0 | 0 | 0 | 0 |

结论：**常规屏（≥700 高）顶栏加 24px 以内几乎免费；紧凑屏预算上限 +16，再多就撞 32px 下限。** 横屏只要不加宽侧栏就无代价。

## 2. 三个方案 + D

### A. 放大 + 合一：一块「牌子」

数字和形状小图进同一朵云；小图用目标数字的颜色 + 第一格有脸（= 「你要拼出的那个伙伴」），2×2 每格 28px。

| | 375×812 | 360×640 | 667×331 |
|---|---|---|---|
| 云主体 | H 100，minW 180，圆角 50，阴影 6px **`#8FC3E3`（比 skyDeep 深一档）** | H 76，minW 140 | 侧栏内数字上、小图下，云 H 76 → 两行 120 |
| 数字 | 72 / lh 80（算式 50、长算式 34）| 52（算式 36）| 52 |
| 小图 | step 28，格 26，2×2 = 64；4 横 = 120 宽（砖 2×4 = 120×64）| step 22，格 20 | step 18 |
| 小图样式 | fill = `colorsFor(n).fill`、edge 2px、第一格 `Face mood="calm"` 14px、整体 `useBreathe` 同步 | 同 | 同 |
| 顶栏 | 104 → **120（+16）** | 80 → **88（+8）** | 侧栏 168 不变 |
| 提示卡 | 84 → 88：标题 18 → 20，详情不变，图标盘 44 → 48 | 56 不变 | 不变 |
| 谁来付 | 页脚 76 → 68（按钮 48 + lip 仍够）；净 +12 | 页脚 52 → 48；净 +4 | 0 |

净 +12 在 375×812 对全部代表站是 0 代价；360×640 净 +4 只影响 17（43→42）；360×568 的 17 仍 ≥ 33。
**要改的测试**：`layout.test.ts:162-163`（268 / 192 常量）、`:169`（SE 361）、`:172-176`；`layout-fit.test.web.tsx:160-179` 读 `LEVEL_CHROME` 自动跟，但 Amber chin 断言 `chin < (card − disc)/2`：card 88、disc 48 → 20 > over 10 ✓；`LevelScreen.test.web.tsx:420-434` 数 `template-preview > div`，加脸子节点仍 ≥ 4 ✓，但 `previewWidth` 若小图改为云的子节点，选择器要跟着搬。
**风险**：云变宽（最宽 ~224）后与左 Amber(12–60)、右菜单(315–363) 的中段只剩 255，长算式「3 = 2 + 1」+ 小图并排放不下 → 规则：**有小图的站用「数字 + 图」，算式站不放图**（Take-away 岛本来就没有 template）。小图进云后 `Spotlight`（`Spotlight.tsx:11-28`）要套整朵云，环会压到 Amber。

### B. 目标搬到工作台：幽灵轮廓

云只留数字（可去掉小图盒，顶栏 104 → 96），形状参考改成工作台上的虚线幽灵：把 `BossOutline`（`BossOutline.tsx:38-66`）泛化为 `TargetOutline`，输入任意 `cells`（模板 / 一排 n 格 / 加法 sideBySide），沿用 2.5px 虚线、第一格睡脸、`lit` 淡色填充（`:68-70`）。

- **摆放：平移固定 vs 自由。** judge 本来就「形状放哪都算」（`BossOutline.tsx:36` 注释：judge never sees it, nothing snaps）。建议 **固定锚点 + 跟随第一块**：开站放在 `bossOutlineCells` 同样的居中位置；孩子第一块落在别处且模板平移后仍在台内 → 幽灵平移到以那块为「头格」的位置（否则留原地）。判定不变，幽灵永远只是建议。
- **吸附：** `resolveDrop`（`layout.ts:194-215`）仍按最近格；只在 `settleOrigin`（`:226`）的 `prefer` 加「优先落在幽灵格」做平手裁决，不改接受集。这样「照着幽灵拼」和「自己拼」都成立。
- **进度：** `lit` = 被积木盖住的幽灵格数（与 boss 入场一样的 pale 填充），盖不在幽灵上的块不点亮——这就是无声的「不是这里」。
- 适用站：ch1-n3/n4/n6/n7/n8（形状）、ch2 加法（并排幽灵）、数量站可用一排；Take-away 岛开站积木已在台上，不适用（但 Compare 岛天然适用）。
- 预算：顶栏 −8，提示卡不变；375×812 的 17 托盘 46→48；紧凑屏同向。
- **要改的测试**：`Stage.test.web.tsx:109-133`（`boss-outline` / `boss-cell-lit` 数量会在非 boss 站也出现）、`LevelScreen.test.web.tsx:1299`（`template-preview` 存在）、`:420-434`（square→line 的宽度比较改为幽灵格数 / 形状）、`hints.ts:847-921` 的 `focus.template` 改指向幽灵。
- **风险**：工作台已有三种「虚」的东西——拖动吸附预览（`THEME.preview` 灰）、示范手 ghost、boss 虚线——再加一种要统一视觉（建议幽灵用目标色 edge 虚线 + 睡脸，吸附预览保持灰实线）。17 的 6×5 台幽灵覆盖大半，和 D-097 boss 已验证的体验一致。顶栏没了小图，ch1-n6「同样 4 个，换个样子」的第二形状靠幽灵换形来表达，要配 `useNod` 级别的变形动画否则孩子看不出变了。

### C. 开场仪式 + Amber + 5 秒再唤起（零 chrome）

每站 `puzzle` 变化时一拍（约 1 s）：
1. 0–450 ms：云 `scale` 0.6 → **1.4** → 1（`withSpring` damping 7，复用 `usePop` 的形状，把 1.32 改参数化）；同时云阴影由 `#A9D5EE` 闪到 `#8FC3E3` 再回。
2. 300–800 ms：小图 `rotate` ±8° 三次（`useNod` 的节奏）。
3. 400 ms：Amber `useNod` 一次 + `translateX +6` 向云探身（她没有手臂素材，用「探身」代替「指」）；或把 Amber 的位置改到云的左下让她看起来托着牌子（`guide.over` 10 → 14 即可，不改 chrome）。
4. 450 ms：两音上行软 chime（和过关音区分，低半度、更短）。
5. **再唤起**：复用 `NUDGE_AFTER_MS` 的空闲计时（`LevelScreen.tsx:47,259-270`，现在 3 s 只脉冲喇叭）：开站后 **5 s 没有任何触摸** → 云 `usePulse` 1.16× 两下 + 同一 chime 轻一度；每站最多 2 次，第一次触摸后取消。
6. `useReducedMotion`（各 hook 已有，`juice.ts:159,177,197`）为真：不缩放不旋转，改 **云阴影加深 + 小图边框 1.5 → 3px 持续 1 s** 的静态强调；chime 保留（声音不是动作）。

成本：动画只；chrome 0。**要改的测试**：`LevelScreen.sound.test.web.tsx` 的开站音频期望（新增 chime 事件）；`badgePops` 若复用，`LevelScreen.test.web.tsx` 里凡断言「开站不弹」的要调整。风险：每站都弹，10 站后孩子习惯化——所以只弹一次 + 最多两次再唤起，不循环。

### D. 提示卡文字：给家长的，还是给孩子的？

- 家长：标题 18px / 详情 14px（`AnswerFeedback.tsx:137-140`），墨 11.6:1、inkSoft 5.0:1 都过 AA，手机臂距可读。**卡本身不算小**；要动也只到 20 / 15。
- 预读者：不读字。她能用的只有 44px 图标盘和喇叭。`✦` 无语义、`↗`「还在拼」抽象、灯泡要学。**真正该放大的是「状态符号」而不是字**——建议：盘 44 → 52，开始态用 Amber 的小头像（话是她说的，和 D-098 一致），调整态保留灯泡，成功态 ✓ 不变；喇叭 40 → 44。字不动。
- 另一层：卡是顶栏下第二个 1.19:1 的白块，和云连成一片——A 里把云阴影加深、卡保持浅，就能把「任务」和「旁白」分成两层。

## 3. 推荐

**现在：C + A-lite**（A 的「合一上色加脸、顶栏 +16 / 紧凑 +8、页脚 −8 / −4」，暂不动卡字号，只放大图标盘）。理由：C 直接打 #4/#5/#9（没动静、没对比、被 Amber 抢戏），零预算、一天工作量；A-lite 打 #1/#6/#7（小图太小、无脸、分离），常规屏免费、紧凑屏 +4 净代价在 17 站只掉 1px。两者合起来覆盖 1.3 里 10 条中的 8 条。
**之后：B 随 Compare / Shape 岛（Phase 23+）**，因为它要动 judge 旁边的 UX（跟随、prefer、三种虚线统一）和一组已 pin 住的测试，而且 Take-away 岛用不上；新岛本来要新内容，顺手把形状参考搬上台。

**下次孩子试玩要观察的 3 个行为**（对比本轮录像）：
1. **开站 2 s 内的第一眼 / 第一指**：孩子是否先看（或用手指）云朵，再去碰积木；本轮是直接伸手拿积木。
2. **形状站的前两块**：ch1-n3「4 方阵」第一、二块是否相邻成 L / 竖排（说明看到了形状），还是习惯性排成一行后等纠正。
3. **5 秒再唤起之后**：云弹两下时孩子是否抬头、说出数字或点云（`prompt` testID 的点击可以计数）；家长「看上面」的口头提醒次数是否下降。
