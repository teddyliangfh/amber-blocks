# Claude 新版：儿童、游戏产品与 UI 复审

日期：2026-10-14。结论：代表玩法与纠错流程已经走通。下一轮应优先让孩子不用读字也知道如何操作、如何改正，再给重复游玩一个具体理由。下面的儿童体验判断是基于成人试玩提出的设计假设，不能替代孩子实际试玩。

## 本次验证

- 阅读 Phase 12 的改动，以及反馈、语音控制、关卡材料、地图和布局实现。
- 重新构建并运行当前静态产物，使用 Codex 内建浏览器的 click / drag 实际操作，没有脚本填写完成记录，也没有合成 DOM pointer 事件。
- 试玩 3+4 的选错伙伴 → 换正确伙伴但分开 → 连接成功 → 逐块数 7；4 方阵的数量正确但形状错误 → 占格弹回 → 改成方阵；10 的卡住状态 → 归还一块 → 5+4+1 成功并刷新保留；17 的诱饵 4+10+5 → 多 2 块 → 换 4 为 2 → 成功并刷新保留。
- 检查 390×844、375×553、667×331；游玩中转屏、短横屏菜单、中英切换、地图定位当前站。
- 不是本轮重新顺序打通全部 19 关；全部关卡的数据与规则由自动化测试覆盖。本轮重点是代表玩法和错误路径。
- lint、typecheck、Web export 通过；35 suite / 449 tests 通过。测试输出有 ProgressProvider 更新未包进 act 的警告，应清理；不是本次浏览器运行报错。
- 浏览器检查的 warn / error 日志为空。没有听取或录制实际语音，没有真机触摸、安全区及 Safari 音频解锁验证。
- 未修改应用源码。新增本报告与试玩截图；构建、测试更新生成的 dist / coverage。

## 已确认的进步

- 选错伙伴、数量正确但未连接、形状不对、成功有明确的不同反馈，整体比只变绿和出现下一站更易辨认。
- 短横屏菜单全部操作可见；667×331 方阵成功的下一站按钮底边为 325px，已在屏幕内。
- 地图返回时能看见当前站，不再回到第一岛开头。
- 形状参考放大；伙伴的单块点数能在真实操作里走通。
- 大数关加入额外伙伴，“把所有组搬过去”不再自动过关。5+4+1 在 quantity 10 中也被接受，保留了组合自由。
- 10、17 的本轮作品刷新后保留。

## 从儿童玩家看：会改错，但还不一定知道该动哪里

### 最需要改善：提示指向物体

实际把四块摆成长条时，反馈是“数量对了，再看看形状 / 看看这个样子，再换一换”。改正方向是对的，但积木和参考图没有任何额外变化。一个不识字的孩子仍要把声音里的“这个样子”对应到屏幕右上的小参考，再自己决定移动哪些块。

同样，3+4 放了 4+2 时，提示“换个伙伴试试看 / 我们先找 3 和 4”，画面没有标出要送回的 2；两组分开时，“接起来”没有连接位置的提示。

建议按帮助层级处理：第一次只给简短鼓励；孩子主动点提示时，轻轻高亮需要关注的参考图或伙伴；再次求助再示范一次拖动方向。不要一开始直接替孩子摆出答案。提示结束后孩子仍能自由选择位置和等价造型。

### 第二个理解门槛：单块与整组长得太像

前面一个方块拖动一个单位，后面相似的方块组成伙伴，抓任意一块却移动整组。数字徽章目前主要表达数量，没有清楚表达抓取范围。10 的关卡又同时有整组与两个单块，容易把“我刚抓的这一块”理解成“为什么其他四块也跟着走”。

建议第一次整组题出现时，用一次很短的示范，清楚显示整个伙伴一起移动；组外轮廓或握把让抓取范围可见。保留单块点数，别把整组拖动与点击计数变成两个隐蔽模式。

### 错误放置与数学错误需要区分

我把方阵题中的块拖到已占用格，积木弹回，反馈仍是原来的“再看看形状”。孩子可能分不清是答案不对，还是那里放不下。

建议无效落点给局部、短暂的提示，例如占用格轻闪、被拖积木轻轻摇一下；取消手势不报错。别让这类操作反馈打断数学语音。

### 大数的可操作性需要真手验证

375×553 的 17 关，本次实测单块是 34×34px。成人鼠标能完成，但逐块点数时对象密集、单位数字和组标签接近。不能据此判断四岁孩子也能稳定点中。

建议真机观察错点、重复点和误拖情况；必要时增加计数命中容差或局部放大，而不是继续缩材料。也应允许家长选择小数和加法内容，不让 17 成为所有孩子必须跨过的门槛。

## 从游戏产品看：闭环成立，重复游玩的理由还弱

现在主要循环是“拖积木 → 系统判断 → 下一站”，这足够验证核心玩法。19 关给了内容长度，但多数关卡的动作和完成结果相似；Boss 大多靠星标、数量和材料复杂度区分，完成后仍是同一张绿卡。

建议先做一个小而清楚的奖励闭环：每完成一个 Boss，让刚搭出的伙伴做一次独特小动作，或者把作品加入一个简单造型册。奖励应来自孩子刚做的作品，让“我搭出了这个”成为记忆点，不需要排行榜、复杂货币或长剧情。

“再玩一次”当前保持题目和材料安排，适合熟悉操作，但可能演变成记位置。建议另外提供“换个摆法”或“再找一种组合”，复用现有判定能力；先提供选择，不自动打乱孩子保存的作品。

大数诱饵提高了选择性，也增加了组合与回退难度。建议第一次整组题少一个干扰因素，完成后再增加诱饵；不要同时引入新拖动方式、较大数域和卡住后回退。两阶段顺序应帮助理解，而不是只表现为章节锁。

章节完成需要收尾：一句明确的“数字岛完成了”，回顾孩子的一个作品，再介绍下一章要做的事。现在完成 17 后直接进入简单加法，进阶的意义不够可见。

## 从 UI 设计看：状态清楚了，操作与信息层级还可收敛

数字目标、蓝 / 琥珀 / 绿卡、白色工作台、沙色托盘已形成稳定视觉关系；形状参考和横屏菜单也有实质改善。建议保留整体调性，不重做整套视觉。

优先调整：

1. **目标与参考更像一个任务。** 数字旁的形状虽放大了，但仍像一个小装饰。给参考一个清楚的关系提示，或求助时在工作台边展示更大的参考，避免只说“这个样子”。不强制在工作台上画唯一摆放位置。
2. **压缩重复信息。** “数量对了，再接起来 / 把它们接起来”重复；可以改成一条主指令，加实际数量状态。成功时大算式已经显示结果，反馈卡只保留简短鼓励和可重听说明。
3. **统一图标语义。** ↻ 同时表示调整答案、再数一遍、再玩一次，容易混淆。调整反馈可用工具 / 小提示图标，重数与重玩结合对象或文字，不只复用同一个旋转箭头。
4. **重听入口更清楚。** 整张卡可点，命中区域很好；但右侧 18px 扬声器在截图里非常小，形状不够清晰。换成清楚的统一图标和按钮外观，让孩子知道这是可以按的。
5. **组数字与点数序号区别开。** 伙伴徽章是组的数量，小圆点是点击顺序；密集时有多套数字。用位置、形状或显隐明确区分，点数完成突出总量，再淡化过程序号。

## 需要修复的工程问题

### P2：布局测试使用了旧的提示栏高度

`src/blocks-ui/devices.ts:38` 仍按 24px 提示栏计算。当前 AnswerFeedback 普通竖屏 84px + 4px 外边距，短屏 70px + 4px 外边距。因此测试舞台比真实舞台分别多算了 64px、50px。

已核对：375×553 的真实 stage 高度 335px，测试 helper 返回 385px。这不意味着本次 17 关溢出——实际没有溢出——但“所有手机尺寸都通过”的几何测试证明范围偏大。

建议统一布局预算常量，并保留直接读取真实页面 bounding rect 的回归；检查所有题型、文案和安全区，而不只测试纯函数。

### P2：内容材料变更未更新版本，旧作品会被清空

本版在 10 / 12 / 17 加诱饵、打乱伙伴、改变备用块颜色，但 `src/content/catalog/index.ts:8` 的 CONTENT_VERSION 仍为 1。

我用上一版 10 关的合法材料构造存档夹具（12 单位，其中一个 5 已在工作台），交给当前 loadArchive：新材料是 16 单位，返回 `issue: repaired`、`work:ch1-n10`，作品变为 null，并存在备份。这个变化有确定原因，不宜只写成“偶发作品丢失”。这是旧版夹具验证，本次新作品刷新正常。

建议定义版本升级策略、增加旧档回归。如果确定清空变更关卡的作品，就明确按升级处理并保留完成记录；如果希望保留作品，需要映射原单位身份并补入新材料。不要把预期升级描述成存档损坏。

### 待验证：纠正语音的“静止”判断未覆盖拖动过程

`correction-voice.ts` 对提交、点数和菜单有活动控制，但 LevelScreen 的 onPreview 没有调用 activity，也没有拖动开始 / 结束信号。上一答案处于调整状态时，孩子长按或慢慢拖动超过 900ms，旧纠正仍可能在拖动中排队播放。

这是源码路径风险，未用实际发声确认。建议以手势激活 / 结束控制等待，别仅靠提交判断孩子已停手；同时观察 900ms 自动提示是否过早打断自主探索。

## 下一轮优先级

1. 修真实布局预算与旧档升级回归，确认新版本不会意外影响作品。
2. 做一次首次拖动 / 整组拖动示范，加入指向物体的可选帮助和无效落点反馈。
3. 做一个 Boss 收尾或作品收藏的小闭环，先给孩子试玩，再决定是否扩更多关卡。

儿童试玩时重点观察：能否自己知道该动哪里；单块与整组是否符合预期；提示能否帮助恢复且不打断探索；过关后是否愿意再换一种摆法。不要用成人操作速度或自动通过来代替这些观察。
