## 1. 项目缘起

最初讨论的是适合四岁孩子、能够鼓励探索与好奇心的手机小游戏。随后目标转为自己开发一个 App，先给女儿使用，以兴趣启蒙为核心，未来再考虑商业化。

孩子最近喜欢数数，也喜欢动画 Numberblocks，因此数学是第一条内容线。讨论中提出通过具体的积木数量与操作体验理解数字，而不是一开始就做文字题、算式题或刷题训练；具体实现方式需在 PRD 中确认。

希望逐步参考澳洲学前班及小学阶段的学习内容，但具体州、学校体系与正式课程映射尚未确认。

## 3. 产品方向：已经讨论，但仍需 PRD 确认

以下是建议，不应被后续开发者误读为用户已全部批准的需求。

- 先把一个小游戏做成完整、可反复探索的体验，再扩展内容。
- 旧原型建议 1–5；当前用户已提出 6、9、17，数域与大伙伴支持按章节文档收敛，不把五块当正式上限。是否引入 0，另行设计。
- 可探索点数、按数量搭积木、拆开与合并、改变排列但保持数量、多一个 / 少一个等概念。
- 共享积木空间仍复用；最新主入口为章节地图与短题 / Boss，自由沙盒改作补充。此项取代旧“自由邀请作为唯一主线”的建议，不按速度做考试。
- 语音与视觉示范应让孩子不依赖识字；中英双语语音已确认，切换和默认播放方式仍需设计。
- 建议采用原创角色、声音、故事和美术；参考数学表达，不直接复用 Numberblocks 的角色外观、音乐、片段或其他素材。未进行任何授权或知识产权审查。
- 建议避免倒计时、惩罚性失败、排行榜、连续签到、随机奖励与儿童端付费诱导。
- 首版建议核心玩法不依赖在线业务后台，无账号、无广告、无儿童个人信息上传；网页离线缓存范围单独确认。
- 不宣称“提升智商”或保证提前掌握学校课程；真实效果需要观察与评估。

### 手机网页与全屏：新增需求及交付方案

- 用户新增需求：主要在手机玩，可以直接打开网站，最好有全屏游戏模式。
- 当前 PRD 据此采用手机 Web 优先的首轮交付方案；原生 App 与商店发布仍未排期，不改变已选择的 React Native。
- 建议三层显示体验：普通浏览器内的可用区域铺满布局、能力允许时的真正全屏、可选的主屏幕独立启动。
- Fullscreen API 需要用户操作触发，存在兼容与请求失败情况；不承诺所有 iPhone / Android 浏览器都能隐藏地址栏。[MDN 全屏 API](https://developer.mozilla.org/en-US/docs/Web/API/Element/requestFullscreen)
- 主屏幕 `standalone` 模式可以提供没有普通地址栏的独立窗口，但可能保留系统状态栏；不等同于真正全屏。提供可跳过的家长操作说明，不强迫安装。[显示模式](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Manifest/Reference/display)、[WebKit 主屏幕 Web App 说明](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/)
- 网页首次访问需要加载资源；添加到主屏幕不自动保证离线。缓存与断网重新打开的范围应独立评估。[Expo PWA 指南](https://docs.expo.dev/guides/progressive-web-apps/)
- 竖屏优先是可讨论的布局建议，尚不是用户已确认的屏幕方向。

### 中英双语：新增确认及建议方案

- 用户在“第一版语音用英文、中文还是双语”的上下文中选择双语，记录为中文与英文语音均进入第一版范围。
- 建议核心数数、引导和反馈语音两种语言完整对应，使用同一套数学规则；关键界面文案的中英版本是配套设计建议。
- 建议每次只播放一种语言，由家长选择或切换；“双语”不默认等于每一句连续播放中英两遍。
- 切换语言应停止旧语音，但不重置积木、数量、分组或活动进度。
- 默认语言、是否需要连续双语播报、中文音种、英语口音和录音制作方式均未确认。

### Numberblocks 难度、形状与颜色：新增方向

- 用户提出按 Numberblocks 的课程 / 视频难易程度参考内容，并加入形状组合、颜色组合；这是已表达的产品方向，不是确认一次性覆盖所有视频或所有活动。
- 已核对官方分级：Level 1 从 1–5 的数感内容开始；Level 2 扩展到 10，并涉及形状和规律等。它是内容参考，不是四岁儿童的达标要求。[官方学习说明](https://www.blocksuniverse.tv/numberblocks/how-it-works)
- PRD 以 How to Count、Stampolines、The Whole of Me 的点数、重排不变总量、部分—整体概念作为首轮参考锚点；不复用剧情、角色、音乐或视频素材。[NCETM Series 1](https://ncetm.org.uk/classroom-resources/ey-numberblocks-series-1/)
- 建议共用一个探索空间，分别控制数感、形状与空间、颜色与规律的难度；引导任务每次突出一个概念，不用看过的集数自动判定掌握或解锁内容。
- 首轮建议仍使用相同的单位方块做点数、自由重排，并提供可选双色配色。颜色分类、AB 规律和独立几何拼片随后逐项验证；这些范围仍待确认。
- 数字方块重排不改变块数；几何拼片组成一个图案，不等于拼片数量变成一块。颜色不永久绑定到数字或形状。
- “颜色组合”暂理解为配色、分类与规律。是否包含颜料混色尚不明确；混色需独立设计，未纳入首轮原型。

## 4. 澳洲教育内容的衔接方式

建议把课程作为内容设计的参考地图，而不是把小学学习目标变成四岁儿童的硬性进度要求。

- 学前阶段可参考 EYLF V2.0，重视基于儿童兴趣、经验及个体差异的游戏化学习。[ACECQA 官方说明](https://www.acecqa.gov.au/nqf/national-law-regulations/approved-learning-frameworks)
- Australian Curriculum V9 的 Foundation 数学涉及数词与数字的联系、点数和快速识别少量物体，以及 10 以内集合的分拆与组合；其中 0–20 等是 Foundation 年级的内容方向，不是本项目对四岁儿童的达标要求。[ACARA 官方内容与样例](https://www.australiancurriculum.edu.au/resources/work-samples/mathematics/foundation/ws03-numbers-to-20)
- 后续确认所在州及教育体系，再核对当地课程实施要求；本项目目前未获得课程认证或教育效果验证。
- 新增形状与规律方向可参考 Foundation 的熟悉形状分类 / 创造、重复规律；ACARA 样例包含按颜色和形状整理物体。自由配色或几何创作不因此被宣称为已完成课程指标。[ACARA 官方样例](https://www.australiancurriculum.edu.au/resources/work-samples/mathematics/foundation/ws02-sorting-shapes-and-objects)
- 建议设置现实活动的桥接，例如试玩后用真实积木、餐具或玩具重现同一个数量关系。

## 5. 技术选型的讨论经过

1. 讨论过 Web / PWA、原生手机 App 和跨端方案，也考虑过 Phaser 等偏游戏渲染的工具。
2. 对简单 2D 数学互动，React + TypeScript 可以快速验证玩法；但普通 React DOM 界面不等于可直接转换成原生 React Native 界面。
3. 因用户熟悉 React / React Native，并考虑未来手机和平板 App，助手建议 Expo + TypeScript + React Native Web 从同一项目起步。
4. Flutter 也是可行候选，具备绘图、动画与游戏工具生态；用户已经做过 Flutter，并非从零接触。
5. 用户最终选择 React Native。当前不再并行推进 Flutter 方案。

- 建议默认：Expo + TypeScript + React Native Web，当前 PRD 按手机网页试玩优先收敛。
- 尚未确认：具体手机和浏览器、原生版本的优先级及 iOS / Android 商店发布顺序；平板不是首要设计设备。
- 尚未确认：横屏 / 竖屏、最小系统版本及支持设备范围。
- 尚未安装或锁定任何 SDK / 第三方库版本。

### 建议的实现方向

- 使用跨端 `View`、`Text`、`Pressable` 等组件，避免核心玩法依赖浏览器 DOM。
- 数学规则、关卡数据与状态转换尽量使用独立的 TypeScript 模块。
- 简单积木画面可先用组件，必要时增加 `react-native-svg`。
- 拖拽和动画可评估 Gesture Handler / Reanimated，音频可评估 `expo-audio`；这些是候选库，不是必须立即引入的完整清单。
- 当前玩法不要求完整游戏引擎，也不建议初版就增加复杂绘图层、物理系统或后台。
- 跨端不意味着零适配：触摸、音频、布局、生命周期仍需分别验证，尤其应尽早测真实设备。
- Expo Go 可以用于快速实验；正式开发涉及特定原生模块或内购时，应使用合适的 development build，而不能假设 Expo Go 支持全部功能。

参考：[Expo 与 EAS 的区别](https://docs.expo.dev/workflow/overview/)、[Expo Web 与 React Native Web](https://docs.expo.dev/workflow/web/)。

## 6. 免费、开源与商业化的讨论

- Expo 开源工具使用 MIT 许可，免费且允许商用；使用相关代码时需遵守许可条件。[官方许可](https://github.com/expo/expo/blob/main/LICENSE)
- EAS 是可选云服务，有免费额度和付费方案；不强制订阅，也可本地构建。[官方说明](https://docs.expo.dev/workflow/overview/)
- Apple 开发者费用、App Store 交易规则和其他服务成本，与 Expo 框架费用分开。具体金额与条款应在发布前重新核实。
- App Store 是讨论过的潜在商业渠道，不代表一定更容易获取用户或盈利，也不代表已确定 iOS 首发。
- 曾建议先让家庭验证玩法，再考虑“完整免费体验 + 一次性解锁”；订阅仅在有持续内容价值时评估。收费模式尚未决定，首版建议暂不实现内购，待 PRD 确认。
- 未来面向儿童上架时，需要核查家长门、隐私、第三方 SDK、外链及购买等限制；家长门不等同于数据收集的家长同意。[Apple 当前审核指南](https://developer.apple.com/app-store/review/guidelines/#kids-category)

## 7. 市场使用率讨论的结论

市场使用率不能直接决定本项目的技术选型，且不同分母不可混用。

- 没有据此得出“某框架全市场胜出”或“AI 必然更擅长某框架”的结论。
