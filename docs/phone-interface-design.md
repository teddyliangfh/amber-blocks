## 历史附录：v0.7 拖放与小球实验

以下第 1–9 节保留上一轮手感与结构实验。小球 / 两色内容不再代表默认玩法；与当前顺序冲突时，以“当前方案”、PRD v0.8 和两阶段文档为准。

## 1. 用户反馈与本轮修正

用户明确提出：

- 积木必须是看得见、拿得起来的物件，不是点一个按钮生成的数字或占位符。
- 拿取和移动以 drag and drop 为主，提起、拖动、放下、接合和收回要接近真实玩具的感觉。
- “给三个小座位摆积木”的数量匹配情境太无聊，不再作为默认入口或候选示范。

因此，上一版“点击拿一块 → 选中 → 点击空位移动”的主路径废弃；四列三行可见空位及座位任务不延续到新草图。点击取放只保留为未来可选无障碍替代，不作为首要玩法。

真实手感不等于承诺完整物理仿真。当前先把物件可见性、直接操作、连贯反馈和可预期后果做清楚；积木坍塌、受力计算及完整物理引擎不属于本轮。

## 2. 主入口：先看到玩具，再自己动手

本轮建议主入口是同一个自由工坊：

- 工作区留出可自由摆放的大空间，没有可见棋盘格、待填座位或答案轮廓。
- 底部托盘明确放着有限的一批积木；本轮用五块等大方块，五块上限只是原型假设，未获得用户对正式数域的确认。
- 孩子直接从托盘抓住一块、拖到工作区、松手放下。托盘对应位置空出来，不在手指下悄悄复制第二块。
- 舞台上的积木也能随时提起，单块拆开或拖回托盘；无须先进入“编辑模式”或找到删除按钮。
- 简化“放小球”作为动作与后果实验入口，帮助观察不同摆法如何影响小球落下和接触；不要求摆出指定数量。

小邀请未来可作为自然的探索提示，但不是必须接受的任务列表；它不能遮住物件或把自由工坊改回填空题。

## 3. 手机布局假设

- 首轮仍用竖屏评审，正式横竖屏方向尚未确认；草图不能替代方向与真实手机安全区域设计。
- 顶部保留返回 / 玩好了、产品名称及家长区；语言、说明和全屏设置不挤占儿童抓取区。
- 中间以工作区为视觉主角；物件的边缘、阴影、位置和运动首先传达状态，文字只是家长评审辅助。
- 底部是可见的实体积木托盘，而非“拿一块”的主按钮。拖回托盘时出现明确收回预览。
- “放小球”是次级实验入口，不弹题、不抢手指、不连续自动补球。小球不是计数积木。
- 每个已经稳定放下的连接簇显示自己的积木数量。拖动期间隐藏工作区数量标签，避免用未提交的位置给出不断跳变的答案。
- 相邻连接不靠颜色表示；边缘对齐和接触才是视觉关系。配色不绑定数字，也不能是唯一的操作线索。
- 颜色、尺寸、圆角、阴影和图标仍为设计参数，未形成已批准视觉规范。正式无识字体验还需要语音或动作示范验证。

## 4. 抓取、移动、接合与收回

| 阶段 | 孩子看到 / 感觉到什么 | 提交规则 |
|---|---|---|
| 按住可见积木 | 当前草图立即提起同一块的预览，保留清楚来源 | 只有有效松手才提交；轻触后归位不新增库存，手势阈值需真机调整 |
| 提起 | 积木轻微抬起、阴影加深，原位置变空或保留清楚的来源提示 | 使用同一积木身份，不生成第二块 |
| 拖动 | 物件跟随手指，自由经过工作区 | 位置尚未提交；隐藏数量标签，不在每帧写入历史 |
| 靠近另一块 | 接边磁吸预览，能看清将接在哪一边 | 仅提示候选落点，不提前合组或改数量 |
| 松手放下 | 物件短暂落定，取消提起阴影 | 提交有效落点，再计算接边、连接簇及数量 |
| 单块拆开 | 只拿起被抓到的一块 | 不因已经接边而隐式搬走整组 |
| 拖回托盘 | 托盘明确高亮可接收位置 / 区域 | 松手后才收回；路过托盘不删除对象 |
| 取消 / 中断 | 恢复到手势前的稳定位置与来源 | 不丢块、不多块、不把试探中的吸附当作已完成动作 |

交互边界：

- 首轮同一时间只处理一个积木拖动；第二根手指不能接管正在拖的块，也不能触发另一次取块。
- 轻触不得同时触发拿取、移动、计数和实验。未来提供点按无障碍替代时，应有明确独立模式。
- 可以接边，但不能完全重叠、藏在工具栏下或离开可触碰区。无效落点回到原稳定位置，不悄悄跳到孩子没选择的远处。
- 拖到屏幕边缘不是删除；拖动取消、系统打断或离开页面时撤回未提交手势。
- 吸附只做短距离接边帮助；不要把自由摆放变成可见格点，也不替孩子自动整理成漂亮作品。
- 一次松手提交是一项操作；撤销如加入，应撤销整项取放，而非逐帧倒退。

## 5. 连接簇与数字显示

本轮“连接簇”是稳定放下后实际接边的方块集合，不等于孩子已学会的数学分组概念。

- 单块为一个簇；接边后的块可合成更大的簇。仅靠得近、颜色相同或正在预览，不视为已经连接。
- 抓走连接簇中的一块后，应按剩余接边关系重新计算；必要时变为两个或多个簇。
- 每个簇的数字对应簇中积木身份数，不是形状宽度、高度、面积估计，也不是小球数。
- 所有已放下簇的块数合计等于工作区已提交的积木数量；托盘中的块不计入工作区。
- 拖动时隐藏数字；取消后恢复原显示，提交后显示新关系，不能把过渡位置当作最终数学事实。
- 单块拖动始终只搬这一块，不隐式引入整组拖动、整组旋转或粘死机制。
- 数字自动显示是系统的状态反馈，不是“孩子已经主动点数”或“掌握拆合”的证据。

未来主动数数与双语短语音仍需要独立设计，不在本轮新草图中假装已经实装。

## 6. 动作产生后果：简化小球实验

本轮草图已加入“放小球”，让积木摆放影响一个可见结果：

- 小球从固定或清楚可见的位置落下，简化重力与碰撞反馈。
- 孩子可以改变积木高度、间隙、接边方式，再试一次，观察碰到哪里、哪里能通过。
- 已放下的积木在本轮视为固定障碍；小球反馈不代表积木受力、摇晃、坍塌或任意真实滚动已实现。
- 实验没有正确造型、指定块数、通过分数或自动难度升级。
- 本轮小球按当前已提交位置计算接触，正在提起的块暂不参与碰撞；不播放预制旧轨迹。若正式版本改为停止 / 重开实验，也需清楚反馈，不能假装仍在响应新作品。
- 实验中的小球、轨迹与装饰不进入积木数量计算，也不改变五块有限库存。

这只是交互探索，不是完整物理沙盒或已验证的科学教学活动。

| 会动的小生物 | 接成长条 / 矮宽身体、换颜色 → 呈现不同运动 | 同量异形、颜色顺序和重复 | 本轮不实装；不声称自动识别任意作品 |

这些提案仍须验证兴趣与操作负担。不能为了方便验收，把它们改写成“摆出指定数量才能看动画”的固定题。

本轮独立草图已通过桌面浏览器的指针拖出、有限库存、接边吸附、连接簇数量、拖回、撤销、取消手势、拖动隐藏数字、无效重叠不提交、小球运动、切语言保留物件、退出返回与键盘备选检查；另执行仿真触屏拖放 / 取消检查。在 320 / 390 / 736 像素预览的明暗主题中检查横向溢出与操作区域，并查看截图。

下一次优先检查：

1. 指针从托盘取出同一块、松手提交、拖回、取消和连续操作是否始终守恒，不丢块、不复制。
2. 子块从连接簇拆下时只移动这一块；数字在稳定状态对应真实簇，拖动不显示过渡答案。
3. 磁吸预览是否明确、能否自由放下；边界、重叠和托盘收回是否可预期。
4. 小球运动是否确实依赖当前摆放；布局改变后不沿旧轨迹继续演示。
5. 再补真实手机触摸、安全区域及短语音，然后由家长陪同观察孩子是否主动反复尝试。
6. 依据孩子具体行动决定是否扩展塔、桥或小生物，不以停留时长、完成题量或成人评审代替兴趣证据。
